# 用 SMOTE 合成少数类

类别不平衡时，若把少数类样本复制很多遍，决策边界会围着这几个重复点打转，训练误差下降，换一批数据就失效。SMOTE 不复制原行，而是在两个少数类点之间插一个新点。

## 做法

只在少数类内部找邻居，距离用欧氏距离。对少数类样本 `a`：

1. 找出它在少数类中的 `k` 个最近邻。
2. 按希望补到的数量，从这 `k` 个里随机抽若干个，记其中一个为 `b`。
3. 在线段上取点：`a + r * (b - a)`，其中 `r` 是 0 到 1 之间的随机数。

新点的每个特征都是两端的加权平均，标签仍是少数类。多数类一行都不增加。

## 数字例子

少数类只有两个点：`a = (1, 2)`，`b = (5, 2)`。取 `r = 0.25`。

新点 = `(1, 2) + 0.25 * ((5, 2) - (1, 2)) = (1, 2) + (1, 0) = (2, 2)`。

它落在两点连线上，不是第三份拷贝。若 `r` 换成 0 或 1，会退化成端点本身，所以实现里通常取开区间，避免白合成。

假设原来少数类 30 条、多数类 90 条，想接近 1:1，就大约再合成 60 条。每个少数类点平均要贡献 2 个新邻居方向。`k` 至少要大于每次抽取的邻居数。

## 缺陷

`k` 没有公式，只能试。`k` 太小，新点挤在局部；`k` 太大，会连到少数类里很远的离群点，线段可能穿过多数类区域，制造噪声。

算法也不区分「安全点」和「贴在边界上的点」。边界点的邻居方向若指向多数类，插值会落在两类中间，分类器更难。另外，少数类内部若还能分成几团，全局按同一个比例去插，小团仍可能偏少。这是类间平衡了、类内仍不均衡。

纯随机过采样没有插值，过拟合更重；欠采样丢掉多数类，可能扔走有用边界。SMOTE 处于两者之间，不是免费的提升。

## 先聚类再插值

KMeans-SMOTE 先对特征空间做聚类，再决定在哪些簇里合成。少数类占优、而且离多数类较远的簇，被认为更安全，合成名额多给这些簇；混杂簇少合成或不合成。这样既能补数量，又少在边界上撒点。聚类个数和 SMOTE 的 `k` 都是超参数：簇太多时每个簇没有足够邻居，簇太少时又退回普通 SMOTE。

`imbalanced-learn` 提供普通 SMOTE；按簇合成的变体有单独的 `kmeans-smote` 包。两者都要求特征已经是数值。类别列要先编码，否则欧氏距离没有意义。合成只能用在训练集上。验证集和测试集必须保持真实分布，否则线下分数会假装不平衡问题已经消失。

拟合之后看两类条数是否接近目标比例，再拿没被动过的验证集看召回和精度，而不是只看合成后的训练集准确率。

## 插值穿过另一类时

平面上少数类两点是 `(0, 0)` 和 `(4, 0)`，多数类有一个点落在 `(2, 0.2)`，紧贴连线。取 `r = 0.5` 会合成 `(2, 0)`，和多数类几乎重叠。分类器若把这一小片划给少数类，多数类的那一点就被包进去。加大 `k` 更容易抽到这种跨空隙的邻居；减小 `k` 又会在局部打转。先看少数类是否分成互不相连的几团，再决定要不要改用按簇合成。只含一个特征的数据做连线没有几何意义，应先确认特征已经是可比的数值，距离才会和「之间」这个词一致。

类别列若用任意整数编码，`1` 和 `2` 的距离会被当成 1，即使这两个编号只是城市代号。合成前用合理的数值化，或只在连续列上插值、类别列另做抽样。合成行的标签恒为少数类，不要把插值结果再交给无监督算法去改标签。邻居数大于少数类条数减 1 时没有足够的邻居，应先把 `k` 降到这个上限以下。
