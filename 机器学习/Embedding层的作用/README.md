# 嵌入层在做什么

嵌入（embedding）的本意是：把一个对象放进另一个空间，同时尽量保住我们关心的关系。在网络里，嵌入层做的是一件具体的事：给每个离散编号配一条固定长度的实数向量，后面的层只跟这条短向量打交道。

## 独热为什么先被用起来

模型吃的是数，不是原始词或城市名。独热的做法是：词表有多大，向量就有多长；某个词只在自己的那一维上是 1，其余是 0。三个城市可以写成：

| 城市 | 向量 |
| --- | --- |
| 杭州 | (1, 0, 0) |
| 宁波 | (0, 1, 0) |
| 成都 | (0, 0, 1) |

离散取值因此变成了数值，线性模型也能分开它们。缺点同样直接：任意两个不同词的内积都是 0，看不出「杭州」和「宁波」比「杭州」和「扳手」更接近。句子长了以后，还丢掉了词的先后。词表到十万时，每行几乎全是 0，矩阵又高又空，乘加都在浪费。

## 降到短向量

设词表大小为 `V`，希望每个词只用 `d` 个数，`d` 远小于 `V`（例如 `V = 50000`，`d = 64`）。嵌入矩阵是 `V × d`。输入若先写成独热行向量，乘上这个矩阵，结果就是取出矩阵的某一行。实现里不会真的构造独热大矩阵，而是拿整数编号去查表。

这 `d` 个数一开始可以随机，然后跟整个网络一起更新。每一维不必由人来命名。训练之后，经常被相似上下文替换的词，向量的夹角会变小。可以用余弦看接近程度，而不是看某一维是不是「年龄」或「性别」。

一组学完后的二维示意（数字是为了说明，不是某次训练的真实结果）：

| 词 | 向量 | 与「单车」的余弦 |
| --- | --- | --- |
| 单车 | (0.8, 0.6) | 1 |
| 自行车 | (0.78, 0.62) | 很高 |
| 雨伞 | (0.1, -0.9) | 接近 0 或为负 |

「单车」和「自行车」挤在一起，「雨伞」落在别处。这就是嵌入层相对独热多出来的东西：相似性变成了几何关系。

## 它不只服务词语

用户编号、商品编号、店铺编号同样稀疏。推荐模型里常把用户和商品各过一个嵌入层，再把两条向量拼接或做内积。编号要连续地映射到 `0 … V-1`；没见过的编号需要一个专门的「未知」行，不能直接拿一个超出矩阵行数的整数去查。

中文若先分词，词表和向量可以对齐到公开的预训练结果，再在自己的任务上微调。预训练只说明别人在大规模文本上学过搭配，不保证业务黑话也有好向量，领域词往往仍要在任务里更新。

## 使用时的尺度

`d` 太小，不同词挤在一起，区分不开；`d` 太大，参数接近独热，又容易记住训练集里的偶然搭配。词表里的低频词可以先合并成未知符号，否则那些行几乎学不动，还占着参数。嵌入层解决的是「离散编号又多又稀疏」，连续特征（金额、温度）通常直接进后面的层，不必再嵌入一次。查表前要把原始编号压到矩阵行号范围内，越界会在取行时直接失败。微调时学习率宜小于其他层，避免把已经成形的几何关系一次冲掉。
