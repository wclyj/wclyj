# 金融风控里的一个监督学习案例

风控建模常把「这笔信贷会不会在观察期内严重逾期」做成二分类。正样本是违约（或欺诈），负样本是正常履约。一张申请表提供年龄、收入、职业、历史查询次数；贷后行为提供还款节奏。标签必须严格发生在特征时间之后，否则用到了未来信息，线下分数会好看，上线就失效。

这类标签几乎总是不平衡的：违约可能只占百分之几。准确率没有解释力，全猜「不违约」也能很高。排序能力看 ROC 曲线下面积；业务上还常看 KS，即好坏样本累计分布拉开的最大差距。阈值按审批通过率和坏账成本来定，而不是按 0.5 概率一刀切。

树模型的提升方法用得很多，因为特征又杂又有缺失，非线性关系多。少数类可以配合重采样或类别权重，但重采样只发生在训练集。拒绝推断是另一个坑：历史上被拒绝的人没有真实还款，若直接丢掉，模型学到的是「当初愿意批的人」，不是全体申请人。

上线前用时间切分做验证：用较早月份训练，用较晚月份考试。随机打乱再切分会把同一人的前后记录分到两边，分数偏乐观。
