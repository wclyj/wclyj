# 两层栈式融合怎么落成矩阵

栈式融合的原理可以收成两张表。第一张供元模型训练，第二张供元模型考试。两张表的列必须一一对应：每一列是同一个基模型家族的预测。

## 先切开，再出折

假设原始训练矩阵是 `X`，标签 `y`。留出最后 20% 当最终考试集 `(X_test, y_test)`，前 80% 叫开发集 `(X_dev, y_dev)`。元模型只能在开发集的出折预测上学习，考试集从头到尾不参与任何 `fit`。

开发集再做 K 折，记折数为 `F`。准备

- `blend_train`，形状 `(len(X_dev), M)`，`M` 是基模型个数，初值 0
- `blend_test`，形状 `(len(X_test), M)`，初值 0

对第 `j` 个基模型：

1. 再建一块临时表，形状 `(len(X_test), F)`，用来接每一折对考试集的预测。
2. 对每一折：用「非本折」的开发集行拟合，本折行只做预测。把预测写进 `blend_train` 的本折那些行、第 `j` 列。
3. 同一份已经拟合的模型，立刻预测整份 `X_test`，写入临时表的第 `f` 列。
4. 折循环结束，临时表按行求平均，写入 `blend_test` 的第 `j` 列。

于是开发集的每一行，在每个基模型下都恰好被预测一次，而且预测它的那次拟合没见过它的标签。考试集的每一格则是 `F` 个折模型的平均。

三个基模型、开发集 1000 行、考试集 200 行、5 折时：`blend_train` 是 `1000 × 3`，`blend_test` 是 `200 × 3`。临时表在循环内是 `200 × 5`，平均之后丢掉。

元模型（常用逻辑回归，也可以是另一棵提升树）执行 `fit(blend_train, y_dev)`，再 `predict(blend_test)`。分数用 `y_test` 计算，这份 `y_test` 没有进过任何一层的拟合。

## 二分类存什么

二分类若只存 0/1 标签，元模型只能看到硬决定，丙模型「很犹豫的 0.51」和「很确信的 0.99」变成同一个 1。更常见是存正类概率，每个基模型仍占一列。概率要来自同一折、同一次 `predict`，不能训练集上用概率、考试集上用标签。

## 多分类时列会变宽

类别数为 `C` 时，每个基模型对一行要输出 `C` 个概率。`blend_train` 的列数改成 `C * M`，不再是 `M`。第 `j` 个模型占据列区间 `[j*C, (j+1)*C)`。

本折预测写成：

`blend_train[本折行, j*C:(j+1)*C] = 该折模型对验证片的各类概率`

考试集没有「本折」可以分配，所以是把每一折的概率矩阵加到 `blend_test` 的同一段列上，最后除以 `F`。漏除会让考试集的概率尺度比训练列大 `F` 倍，元模型等于在用错误单位考试。

`C = 4`、`M = 3` 时，两张表的宽度都是 12。若仍按二分类写成宽度 3，概率向量会被截断或错位，元模型对不上列。

## 一组能手算的形状

开发集 4 行，2 折，2 个基模型，二分类，只存正类概率。

折 0 的验证行是 0 和 1，折 1 的验证行是 2 和 3。

模型 0：

- 在行 2、3 上拟合，预测行 0、1 得到 0.2、0.8，并预测考试集得到向量 `t0_a`
- 在行 0、1 上拟合，预测行 2、3 得到 0.4、0.1，并预测考试集得到向量 `t0_b`
- `blend_train[:, 0] = [0.2, 0.8, 0.4, 0.1]`
- `blend_test[:, 0] = (t0_a + t0_b) / 2`

模型 1 用同样的折再填第 1 列。元模型看到的是 `4 × 2` 的矩阵。任何一列若整列相同，说明该模型没有学到东西，应在进元模型之前删掉。

## 实现时最容易泄漏的两处

一是先用全部 `X_dev` 拟合基模型，再让它对 `X_dev` 自己预测，拿去训练元模型。行与行之间的预测都「见过答案」。出折的意义就是堵住这条路。

二是考试集的标签被拿去调基模型的轮数或阈值，调完又用同一份考试集报告最终分数。折内可以有验证片来做早停，最终分数只能来自从未参与选择的那一份。

基模型彼此的随机种子、特征子集可以不同，列与列的相关性会下降，元模型更有东西可学。相关度极高的两列留一列即可。

## 泄漏时数字会好看在哪

4 行开发集，真实标签 `[0, 0, 1, 1]`。一个过拟合的基模型若在全部 4 行上拟合后再预测这 4 行，可能得到 `[0.05, 0.08, 0.93, 0.97]`。元模型几乎只学一条阈值就能在开发集上全对。换成出折之后，同一模型对没见过的两行也许只给出 `[0.42, 0.61, 0.55, 0.48]` 这种没那么极端的数。元模型在出折列上的准确率会下降，但这才是它在新数据上能指望的输入。用前一种列训练、用后一种列考试，尺度对不上，分数会突然变差，看起来像「融合有害」，其实是两列的生成方式不一致。

多分类时再举一个错位。`C = 3`，`M = 2`，宽度应为 6。若第二个模型的概率仍写进第 1 列而不是第 3 到第 5 列，元模型会把「类别 0 的概率」和「类别 2 的概率」当成同一含义。检查办法：每一行上属于同一模型的 `C` 个概率应加总接近 1。加总不是 1，说明切片写错或忘记了按折平均。

考试集平均之前，先看各折预测的均值是否接近。某一折若整列偏离其他折很多，那一折的拟合可能没收敛，应先重训该折，再决定要不要进平均。直接平均会把坏折的偏移带进 `blend_test`，而 `blend_train` 里并没有同样的坏列，两边再次不一致。

回归任务不要把这套矩阵做成 0/1。每个基模型对一行只输出一个实数，`blend_train` 的宽度仍是基模型个数。对折预测求平均的做法不变。若某个模型输出的尺度比别的模型大十倍，线性元模型还能靠系数补偿，树模型的切点会被大尺度的那一列支配。可以在进元模型之前，用开发集出折列的均值和标准差把每一列标准化，考试列使用同一组均值和标准差，不能在考试列上重新估计。
