# 袋装、提升，以及两套常用实现

集成学习用多份学习器共同完成一次预测。单份学习器可以是树、线性模型或其他能拟合的东西。差别在于这些学习器怎样产生、预测时怎样合并。下面按「可并行的袋装」和「必须按顺序补残差的提升」分开，再落到随机森林、AdaBoost、梯度提升树、XGBoost 和 LightGBM。

## 两种依赖关系

袋装（Bagging，bootstrap aggregating）里，每一份学习器只看自己抽到的那份数据，彼此不读对方的结果，因此可以同时训练。预测阶段再把它们收拢：回归取平均，分类取多数票。

提升（Boosting）相反。后一份学习器的训练目标依赖前一份已经犯下的错，所以逻辑上是串行的。串行不等于实现里不能并行：同一棵树内部，不同特征的增益仍可以分线程去算。不要把「树与树之间串行」和「一层结点里的特征扫描并行」混成一件事。

加法模型把这个串行写清楚。强预测是若干弱预测的加权和：

`F_M(x) = Σ β_m h(x; a_m)`

`h` 是第 `m` 个弱学习器，`a_m` 是它自己的参数（例如树的结构），`β_m` 是它在总和里的步长。前向分步不去同时优化所有项，而是固定已经得到的 `F_{m-1}`，只求新的一项：

`F_m(x) = F_{m-1}(x) + β_m h_m(x)`

每一轮的优化面因此窄很多。不同算法的分歧，主要是 `h` 拟合什么、`β` 怎么取、样本在下一轮是否改权重。

## 袋装与随机森林

有放回地抽出和原训练集一样大的子集，大约会有三分之一的原始样本抽不中，这些抽不中的样本可以拿来做包外估计，不必再单切一份验证集。每棵树在自己的子集上长成，预测时取平均或投票。平均能抵消各棵树因抽样不同而出现的抖动，所以袋装主要压方差。若基学习器本身非常稳定（例如强正则的线性模型），重抽样对它影响小，袋装的收益也小。树不稳定，特别适合拿来袋装。

随机森林 = 袋装 + 决策树，再加第二处随机：每个结点分裂时，不在全部特征里找最优切点，而先随机抽一个特征子集，只在子集里挑。分类问题里这个子集的宽度常取特征总数的平方根附近，回归常取三分之一左右，都是起点而不是定律。

两处随机让树与树的相关度下降。相关度若接近 1，平均几乎没有方差收益。相关度下来之后，即使单棵树比「用全部特征长成的那棵」更差一点，森林的测试误差仍可能更好。森林并没有取消单棵深树容易记住噪声的倾向，而是用平均把这种记忆冲淡。特征很少、样本也很少时，子集再一抽，切点几乎是乱的，森林不会自动变准。

预测设备会不会在未来 30 天故障时，可以同时训练一棵不限制深度的分类树和一座森林。树的训练误差往往更低，换一个月的数据就明显变差；森林的训练误差没那么低，但月份之间的波动更小。这就是方差下降的经验表现。要解释「哪个传感器最有用」，可以看森林里该特征被选中后不纯度平均下降多少，这是相关意义下的重要性，不是因果。

## AdaBoost：把注意力挪到分错的样本

AdaBoost 不改标签，改的是样本权重。标签取 +1 或 -1。初始时每条样本权重都是 `1/N`。

每一轮在当前权重下训练一个弱分类器 `G_m`，计算加权错误率 `ε_m`（分错样本的权重之和）。若 `ε_m >= 0.5`，这个弱分类器比扔硬币还差，应停掉或换一个基学习器。说话权

`α_m = 0.5 * ln((1 - ε_m) / ε_m)`

错误率越小，`α_m` 越大。然后更新权重：分对的样本乘 `exp(-α_m)`，分错的乘 `exp(α_m)`，再归一化成新的分布。下一轮的弱分类器会更在意上一轮分错的那些点。最终预测是

`sign(Σ α_m G_m(x))`

也就是加权投票，不是简单少数服从多数。

四条样本、初始权重各 0.25。第一轮错了 1 条，`ε = 0.25`，`α = 0.5 * ln(3) ≈ 0.549`。分对的未归一化权重约为 `0.25 * exp(-0.549) ≈ 0.144`，分错的约为 `0.25 * exp(0.549) ≈ 0.433`。三条分对的合计 0.433，和那一条分错的一样多；归一化之后，分错样本的权重约为 0.50，每条分对样本约为 0.167。下一轮只要把这一条分对，就能大幅降低加权错误率。图解里「点变大」就是这个乘法，不是把样本复制进训练集。

指数损失 `exp(-y F(x))` 在前向分步下恰好导出上面的 `α` 和权重更新。所以 AdaBoost 可以看成：加法模型、指数损失、前向分步，这三件事叠在二分类上。回归要换损失，不能照搬这套符号函数。

基学习器常用深度为 1 的决策树桩。树桩很弱，但能接受样本权重。轮数过多会开始拟合噪声点，因为那些点的权重会被反复放大。学习率小于 1 时，相当于把每轮的 `α` 再缩小，通常要配上更多轮。

## 提升树：下一棵树看残差

把基学习器换成回归树，损失换成平方误差，前向分步会变得特别具体。第 `m` 轮要找一棵树，使

`Σ (y_i - F_{m-1}(x_i) - 树(x_i))^2`

变小。括号里 `y_i - F_{m-1}(x_i)` 就是残差。于是这棵新树的训练标签不是原始 `y`，而是当前残差。叶子里放的仍是落叶样本残差的平均（再乘学习率）。

四条样本的目标是 2、4、6、8，特征是 1、2、3、4。初始预测用平均 5，残差为 -3、-1、+1、+3。按「特征 ≤ 2」切开：左边残差平均 -2，右边 +2。学习率取 1 时，新预测变成 3、3、7、7，残差缩小为 -1、+1、-1、+1。再长一棵树去拟合这组更小的残差。学习率改成 0.5 时，第一次只加上 -1 和 +1，预测是 4、4、6、6，给后面的树留出空间，更不容易一步跨过。

分类不能直接拿 0/1 标签当残差去加。常用做法是用对数几率：当前预测先变成概率，用标签和概率的差作为下一棵树的回归目标，最后再把累加的分数映射回概率。

## 梯度提升：残差只是特例

平方损失对预测值的导数是 `预测 - 真实`，所以「拟合残差」等于「拟合负梯度的相反方向再调整符号」。换成别的可微损失，解析残差不一定存在，但负梯度总可以在当前预测处算出来。梯度提升树（GBDT）每一轮做三件事：

1. 用当前模型给出每条样本的预测。
2. 计算损失对这个预测的负梯度，当成回归树的目标。
3. 拟合这棵树，用一个步长（学习率）把它加进总和。

平方损失下，负梯度就是残差，因此提升树是 GBDT 的特例。绝对损失、逻辑损失都能套进同一循环，只要能给出一阶导数。树仍然是回归树，哪怕外层任务是分类。

偏差和方差在这里的角色要分开看。浅树的单棵偏差大、换样本时结构变化相对温和。一棵棵加上去，总和的偏差下降，方差则随着树与树的适应慢慢上升。学习率小、树棵数多、再限制叶子数，是在这条贸易上找位置。学习率大而棵数又多，后几棵树开始拟合负梯度里的噪声。

## XGBoost：把二阶信息和复杂度放进同一目标

XGBoost 仍是前向加树。第 `t` 轮的预测是 `ŷ^{(t-1)} + f_t(x)`，`f_t` 是一棵新的回归树。目标是训练损失加上所有树的复杂度。已经确定的前 `t-1` 棵树的复杂度在这一轮是常数，可以丢掉。

树不是一个可以做普通梯度下降的数值向量，所以对 `f_t` 在当前预测处做泰勒展开，保留到二阶：

`损失 ≈ 常数 + g_i f_t(x_i) + 0.5 h_i f_t(x_i)^2`

`g_i` 是损失对当前预测的一阶导，`h_i` 是二阶导。常数不含 `f_t`，优化时去掉。平方损失下 `g` 就是残差的符号方向、`h` 恒为 1，展开和直接拟合残差一致。逻辑损失下 `h` 随概率变化，靠近 0 和 1 时二阶导变小，模型不会在已经很确信的样本上迈很大的步。

复杂度写成叶子个数 `T` 和叶子分数的平方：

`Ω = γ T + 0.5 λ Σ w_j^2`

`γ` 让多开一个叶子必须带来足够的损失下降，`λ` 把叶子分数往 0 拉。这是显式的方差控制，不是只靠「把树变浅」这种间接手段。

一棵树把样本分进叶子后，同一个叶子共享一个分数 `w_j`。把属于叶子 `j` 的一阶导加总记为 `G_j`，二阶导加总记为 `H_j`，这一轮的目标变成对每个叶子独立的二次函数。对 `w_j` 求导令其为 0：

`w_j = -G_j / (H_j + λ)`

代回目标，叶子 `j` 对损失的贡献是 `-0.5 * G_j^2 / (H_j + λ)`，再加 `γ T`。贡献越负越好。

因此一次分裂值不值得做，比较的是分裂前后这些贡献的差。左儿子 `L`、右儿子 `R`、父亲结点的 `G,H` 已知时，增益为

`0.5 * ( G_L^2/(H_L+λ) + G_R^2/(H_R+λ) - G_父^2/(H_父+λ) ) - γ`

增益为正才分裂。它和信息增益、基尼下降是同一类「分裂前后的纯度差」，只是纯度由损失函数的二阶近似来定义。

### 切点从哪来

精确贪心：对每个特征把样本按取值排序，从左到右扫描，维护左边的 `G,H` 与右边的 `G,H`，每个间隔都算一次增益，取最大。树高 `H`、特征数 `d`、样本 `n` 时，排序占大头，量级大约是 `O(H d n log n)` 这一类，数据进不了内存时很痛。

近似算法先按分位数挑出有限个候选切点，样本放进桶里，只在桶的边界上算增益。全局策略在一棵树开始前就定下候选点，候选点要多一些才接近精确贪心。局部策略每分裂一个结点重新取候选点，候选点可以少一些。XGBoost 的分位数不是对样本一视同仁，而是用二阶导 `h` 当权重：`h` 大的样本对切点位置影响更大，因为它们在二阶近似里更「重」。

缺失值、大量的 0、独热之后的空列，都不必先填一个魔法数。对某个特征，算法试两条路：缺值全部进左，或全部进右，哪条路的最优增益更高，就把缺值的默认方向定成哪一边。这个方向是学出来的，不同结点可以不同。

### 收缩与列采样

真正加进模型的是 `η * f_t`，`η` 常从 0.1 甚至更小开始试。它不改变单棵树内部的增益比较，只削弱这棵树对总和的影响，后面的树还能修正。`η` 减小后，达到同样训练损失所需的棵数上升，两者要一起调。

列采样有两种随机：长树之前先抽一批特征，整棵树都只用它们；或者每分裂一个结点时重新抽。这从随机森林借来，用来降低树之间的相似度，也减少每次扫描的列数。

### 训练时的存储

找切点之前要排序。把排好序的特征列放进块（block）里，块可以复用给后面每一棵树，不必每轮重排。块里是按列压缩的稀疏格式，并带着回到样本梯度的下标。梯度按特征值顺序去读时，内存访问不连续，缓存容易失效。精确算法可以对每个线程准备一块连续缓冲，按扫描顺序把梯度先收集进来再累加。

数据大到磁盘时，把块分放在多个盘上，用单独的线程预读，计算和读盘重叠。压缩后的块在读入时解压。这些是实现细节，但它们解释了为什么同样的加法模型，工程版本会比「每轮用字典排序一遍」快一个数量级。

## LightGBM：直方图、少样本、少特征

LightGBM 也是梯度提升树，目标同样依赖一阶导和二阶导。它假设单机要吃下更多行，多机时通信要省。因此默认不用「每个特征全排序」的精确贪心，而用直方图。

### 直方图

连续特征先离散成至多 `max_bin` 个整数桶。建树时不为每个取值做一次分割尝试，只为桶的边界做。每个桶累加落在里面的 `g`、`h` 和样本个数。扫描一条特征就是扫描几十到几百个桶，复杂度从「特征 × 样本」降到「特征 × 桶数」（在寻找切点这一步）。梯度在直方图里连续存放，对缓存友好。内存里也不再保存每条样本的排序下标。

数值列分桶：取值排序后，尽量让每个桶的样本数接近，但某个取值自己就超过平均桶大小时，它单独成桶，避免把一个高频点拆散。类别列则按出现次数从多到少取前若干个取值各自成桶，极少出现的取值可以并进同一桶，否则桶会被长尾占满。

直方图可以做差。父结点的直方图减去一个孩子的直方图，得到兄弟的直方图。先建样本较少的那一侧，另一侧用减法，建直方图的时间大约少一半。减法要求两边用同一套桶边界。

### 梯度采样与特征捆绑

建直方图仍要扫过样本。GOSS（单侧梯度采样）认为梯度绝对值小的样本，这一轮已经被当前模型拟合得较好，不必每条都留着。它保留梯度最大的那一部分（比例记为 `a`），从小梯度里再随机抽比例 `b`。为了让梯度的期望不被抽样带偏，小梯度样本在累加时乘上 `(1-a)/b`。大梯度样本全部保留，所以决策边界附近的点不容易被丢掉。`a` 和 `b` 太大就退回全量；太小则直方图方差升高，切点不稳。

高维稀疏数据里，很多列不会同时非零，例如不同的独热位。EFB 把这样的互斥列捆成一束，束内用不同的桶偏移，让原来的取值区间错开，从而合成一个新特征仍能还原是哪一列的哪个桶。能捆成多少束，建直方图的列数就降到多少。选择哪些列互斥，像在图上着色：列是点，冲突（经常同时非零）是边，同色才能进同一束。完全互斥很少见，所以允许很小的冲突率，用一点精度换宽度。

### 按叶子生长

按层生长时，同一层每个结点都尝试分裂，哪怕有的结点增益极小。按叶子生长（leaf-wise）每次只挑当前增益最大的那片叶子来分。同样的叶子预算下，损失通常降得更快，但树会在某一支上长得很深。必须同时限制最大深度，否则一条深链会把少数样本记死。调参时 XGBoost 更常直接设 `max_depth`；LightGBM 更常设 `num_leaves`。叶子数上限大约是 `2^深度`，按叶子生长不会铺满完整二叉树，所以 `num_leaves` 设成 `2^深度` 往往偏大，从更小的叶子数试起更稳。

### 并行的三种切法

特征并行加速的是「找最优切点」。传统分法是每台机器只存一部分列，找到全局最佳切点后，由持有该列的机器完成样本划分，再把划分结果广播出去。LightGBM 让每台机器都保留全部列，大家只交换「最佳切点是谁」，然后各自在本地划分样本，不再广播样本走向。通信量下降，内存换通信。

数据并行是每台机器只有一部分行。各自建局部直方图，合并成全局直方图，再在全局直方图上找切点。直方图的桶数远小于行数，合并的体积比传递原始数据小。

投票并行仍是数据并行的变体。每台机器在本地直方图上提出自己的前 `k` 个切分方案，中心结点汇总出大约 `2k` 个候选，只对这些候选收回直方图并相加。不必每次都合并所有特征的完整直方图。行数很大、特征也很多时，这一步省下的通信最明显。

## 怎么选一条路

只想要一个稳的基线，先用随机森林：几乎不用调学习率，也不怕特征尺度。数据有大量类别列、又不想先做编码，CatBoost 那条路更省事。表格数据上要追精度，通常在 XGBoost 和 LightGBM 之间试；行数大、维度稀疏时，直方图、GOSS 和特征捆绑的优势更明显。

无论哪一个，验证集都要按时间或按群体切开，再决定棵数。早停看的是验证损失，不是训练损失。提升树把训练损失压到接近 0 很容易，那不构成模型可用的证据。

## 把一次分裂的增益算完

三份样本在当前预测处的一阶导 `g` 为 -1、0.5、1.5，二阶导 `h` 为 0.5、1、0.5。考虑把第 0 份单独放进左叶，另外两份放进右叶。取 `λ = 1`，`γ = 0.1`。

- 左：`G = -1`，`H = 0.5`，最优叶子分数 `-G/(H+λ) = 1/1.5 ≈ 0.667`
- 右：`G = 2`，`H = 1.5`，分数 `-2/2.5 = -0.8`
- 不分裂时整结点 `G = 1`，`H = 2`，分数 `-1/3 ≈ -0.333`

不分裂的目标值（只看这一结点，叶子数为 1）：

`-0.5 * (1^2) / (2+1) + 0.1 ≈ -0.067`

分裂后叶子数为 2：

`-0.5 * ( (-1)^2/1.5 + 2^2/2.5 ) + 0.2 ≈ -0.933`

目标从 -0.067 降到 -0.933，下降约 0.867。用增益式核对：

`0.5 * (1/1.5 + 4/2.5 - 1/3) - 0.1 ≈ 0.867`

两者一致。注意 `γ` 只减一次：一个父亲叶子被两个儿子替换，净增一个叶子。若增益算出来是负的，就不要裂开，哪怕左右的 `G` 符号相反——罚项已经判定这次裂开不付账。`λ` 变大时分母变大，增益变小，模型更倾向少分裂。这就是正则直接出现在「裂不裂」这个决定里，而不是训练完再剪枝。

换一个切法把三份样本都留在一边是没有意义的，空叶子不参与。扫描排序特征时，左右两边的 `H` 都要为正，否则分数公式的分母只剩 `λ`，数值会非常敏感。二阶导在概率接近 0 或 1 时本来就小，再遇到空侧，应跳过这个候选切点。

## 直方图上的同一刀

把上面三份样本的某个特征取值设为 0.2、0.8、1.3，桶边界定为 0.5 和 1.0，得到三只桶：

| 桶 | 取值范围 | 落入的 g 之和 | h 之和 | 个数 |
| --- | --- | --- | --- | --- |
| 0 | [0, 0.5) | -1 | 0.5 | 1 |
| 1 | [0.5, 1.0) | 0.5 | 1 | 1 |
| 2 | [1.0, 1.5) | 1.5 | 0.5 | 1 |

切点只可能在桶与桶之间。切在桶 0 之后，左边统计就是桶 0，右边是桶 1+2，和上一节的分裂相同，增益约 0.867。切在桶 1 之后，左边 `G = -0.5`，`H = 1.5`，右边 `G = 1.5`，`H = 0.5`。增益为

`0.5 * (0.25/2.5 + 2.25/1.5 - 1/3) - 0.1 ≈ 0.5 * (0.1 + 1.5 - 0.333) - 0.1 ≈ 0.533`

不如前一刀。直方图算法选桶 0 的右边界。精确贪心若在 0.2 和 0.8 之间还有别的样本，可能切在更细的位置；桶把这些位置合并掉了，换来的是只扫桶而不是扫样本。`max_bin` 太小，这一刀的损失会看得见；太大则退回接近精确扫描，内存和速度的好处消失。

父亲直方图若是 `[桶0, 桶1, 桶2]`，左孩子只含桶 0，右孩子用向量减法得到桶 1 与桶 2，不必再扫原始行。减法之后每个桶的个数应非负，出现负数说明左右用了不同的桶边界，结果不能用。

## 采样之后梯度要加回权重

仍用这三份样本，按 `|g|` 排序是第 2 份（1.5）、第 0 份（1）、第 1 份（0.5）。若保留最大的一份作为大梯度（比例按个数粗算为 1/3），再从小梯度里随机留一份，被丢掉的那一份就不能直接忽略。小梯度被保留的比例若是一半，累加时要乘 `(1 - 1/3) / (1/2) = 4/3`，让留下的小梯度代表它和被丢掉的同伴。乘完再放进直方图。不乘这个系数，切点会系统性偏向大梯度样本，相当于改了损失。验证集必须用全量样本评估，采样只发生在建树的那一步。

## 互斥列怎样合成一束

两列独热很少同时为 1：列 A 的取值落在桶 0 或 1，列 B 落在桶 0 或 1。给列 B 的桶号加上偏移 2，合成列的取值就是 0、1、2、3。直方图仍按整数桶累加。分裂若选中「合成列 < 2」，等价于用列 A 的某个桶边界在分；选中「≥ 2」则是在用列 B。偏移量至少是列 A 的桶数，否则两列的桶号重叠，无法还原是哪一列。允许少量冲突时，同时为 1 的行要有个约定（例如只保留列号较小的那列），否则一个样本会想占据两个桶。冲突比例高的列不要捆在一起，那会把两个独立信号加成噪声。

## 通信时传什么

假设 4 台机器、每台 100 万行、特征 200、每列 64 个桶。每个桶存两个浮点梯度。一台机器的完整直方图大约是 `200 * 64 * 2` 个浮点，远小于 100 万行原始数据。数据并行合并的是这个直方图。投票并行若每台只上报 10 个候选特征，中心再挑 20 个收回直方图，通信量大约是完整直方图的十分之一，代价是可能漏掉本地没进前 10、但全局其实最好的特征。`k` 太小会伤精度，太大就退回全量合并。特征并行不传直方图，只传「最佳特征编号、阈值、增益」这样几条标量，然后每台用自己的全量列在本地把样本划到左右孩子。机器内存若放不下全部列，就只能退回「列分开存储、划分结果再广播」的老做法，广播的是每个样本去左还是去右，行数一大，这个布尔向量比直方图还贵。

## 和栈式融合接在一起时

提升树输出的是一列（或分类时每一类一列）预测。它可以作为栈式融合的一个基模型，但出折规则不变：每一折的树只能在该折的训练片上长，验证片上的预测才许进入元模型。用全量数据长完的树去预测训练行，再交给第二层，第二层看到的是过于乐观的残差。早停的轮数也要在折内决定。把第一折的最佳轮数套到所有折上，会让后面的折在不该停的地方停住。

随机森林的预测列和提升树的预测列常常不完全相关，放在一起做第一层比放两份只改了学习率的提升树更有信息。第二层仍建议用简单模型。第一层已经很强时，第二层再上一个深的提升模型，多半是在少数出折噪声上继续拟合。

## 一组可以照着试的起点

这些数只说明数量级，不是最优解。

- 随机森林：树 300 棵，每结点特征数用默认的平方根，最小叶子样本 5。先看验证分数的方差，再决定要不要加树。
- XGBoost：学习率 0.05，树 1000 棵但早停耐心 50 轮，深度 4，`λ` 取 1，列采样 0.8。验证损失几十轮不降就停，不要把 1000 跑满。
- LightGBM：学习率同样 0.05，`num_leaves` 先用 31 而不是 2 的深度次方，`max_bin` 255，特征采样和样本采样都从 0.8 试。行数过百万再打开单侧梯度采样，并检查验证分数有没有掉。

三者用同一套时间切分比较。只在训练片里拟合采样与编码，验证片保持原样。分数接近时，选预测更快、参数更少的那一个，而不是再叠一个复杂的融合。融合是在单个模型已经稳定、且错误模式不同的时候才值得做。

## 包外样本能代替一份切分吗

袋装每次约有 37% 的原始行抽不中。对这些行用「没看过它的那些树」做预测，再和标签比较，就是包外误差。它不需要另切验证集，适合样本很少、再切一刀就不剩多少行的时候。提升树没有这个现成的副产品：每一轮的树都是在全部当前训练集的梯度上长的（除非额外做了子采样），不能把某几行叫成天然的包外。子采样比例小于 1 时，可以记录每一轮没被抽中的行，用该轮的树去评它们，再平均。这个数通常比真实的未来数据乐观一点，因为行仍然来自同一时段。时间切分仍然优先。

## 早停看的曲线

学习率 0.05、最多 1000 棵时，记录每一轮验证损失。常见形状是前几十轮快速下降，然后变平，再缓慢上升。上升说明后加的树在拟合训练梯度里的噪声。耐心设为 50，表示损失连续 50 轮没有刷新最优就停，并回退到最优那一轮的棵数，而不是停在第 1000 轮。耐心太短会停在还没走平的地方；太长会把已经上升的段也算进模型。最优轮数是数据的函数，换一份验证集就会变，所以这个数不能在看过最终考试集之后再改。

把学习率降到 0.01，下降段会拉长，最优棵数往往变成原来的数倍，极限损失可能略好，训练时间也成倍增加。两条曲线都要画在「验证损失对棵数」上，而不是只比较最后一轮。最后一轮在大学习率下常常已经过拟合，比较它会得出错误的输赢。

## 一层结点的代价

按层生长时，深度 6 的满二叉树有 64 片叶子，每一层的结点都要找切点。按叶子生长时，若 `num_leaves = 31`，实际只做大约 30 次分裂，每次都选当前增益最大的叶子。同样的叶子预算，按叶子生长把分裂花在更有用的地方，但某一支可能独占很多层。若不设最大深度，一条链可以长到几十层，训练行里的个别异常点会被单独划出去。深度上限和叶子上限要同时在，缺一不可。验证分数若对 `num_leaves` 从 31 调到 63 几乎不动，就停在 31，省下的是每一轮的直方图扫描，不是一句空的正则口号。

缺失值方向也要在验证里看一眼。若某一列缺失占九成，算法仍会给它选一个默认方向，增益可能来自「缺失 vs 非缺失」这一刀，而不是数值大小。业务上若缺失代表未采集而不是一个稳定状态，应先做成显式指示列，再让数值列只在非缺失行上分裂，避免把采集偏差当成规律。

叶子分数算出来之后还要经过收缩才写进总和。上面那次分裂若增益是 0.867，左叶分数约 0.667、右叶约 -0.8，学习率 0.1 时真正加上的是 0.067 和 -0.08。下一轮的一阶导、二阶导要在这个新预测上重算，不能沿用旧的 `g` 和 `h`。沿用旧梯度等于没把这棵树加进去。早停比较的也是加完收缩后的验证损失。收缩前的叶子分数很大，不代表对验证集的影响同样大。

多机合并直方图时，浮点相加的顺序会让各台机器的增益差一个很小的尾数。比较最佳切点时要用稳定的并列规则，例如增益相同就选特征编号较小的，否则两台机器可能在同一层选中不同切点，后面的样本走向就分叉了。这种分叉不会体现在单机复现里，只在分布式对账时出现。调试时先把桶数和线程数固定，再看切点是否一致。

类别特征若直接按整数大小去切，编号 1 和编号 2 会被当成有次序。没有次序时，应改成按类别统计量分桶，或交给专门处理类别列的提升实现。错误的次序会制造虚假增益，验证集一换编号方案分数就掉。这和连续特征的阈值切分不是同一件事，调 `max_bin` 也补不回来。单机上先把这几种切分的验证损失对齐，再打开多机；分布式只缩短墙钟时间，不会把一个切错的特征变成有效特征。对齐时固定随机种子和桶边界，否则无法分辨是切分变了还是抽样变了。种子只保证切点可复现，不保证切点对未来样本仍然有效。复现实验时把桶数、学习率和早停轮数一并记在同一份实验记录里，方便事后对照。
