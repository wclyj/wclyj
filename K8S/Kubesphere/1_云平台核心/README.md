# 云平台在提供什么

## 为什么把机器交给云平台

自建机房要自己处理机柜、网络和装机差异。云平台把这几件事收成可申请的资源：

- 同一套虚拟网络和镜像，换一台机器不用重做系统基线。
- 按开着的时间或流量计费，实验结束就释放。
- 控制台点完即可登录，不用等物理上架。
- 硬件故障由平台更换，使用者处理的是实例而不是磁盘灯。

国内常见的有阿里云、腾讯云、华为云、百度云、青云，国外常见的有 AWS 和 Azure。账号到各家官网注册即可，登录后使用官方控制台，不需要从第三方网盘下载客户端。SSH 用系统自带的 OpenSSH，或各平台提供的网页终端。

## 公有云

公有云是租用服务商已经建好的资源池。计算、磁盘和负载均衡都由服务商拥有，用户通过互联网管理。硬件和底层网络与其他客户共用，账户之间用虚拟网络和权限隔开。适合对外网站、办公系统和短期的测试环境。Azure 就是一种公有云。

它的好处主要是：

- 不必先买服务器，账单跟着实际使用走。
- 电源、磁盘更换和虚拟化宿主机由服务商负责。
- 容量可以随负载增加，不必一次性按峰值买满。
- 同一地域里有多台宿主机，单台硬件故障时实例还可以迁移。

可用性常用“几个 9”描述。按一年 365 天、每天 86400 秒估算，99.99% 大约允许 52 分钟不可用，99.999% 大约允许 5 分钟。这是统计口径，不是某一天的承诺，具体以合同里的服务等级为准。

## 私有云

私有云把同样的申请方式留在一个组织内部。机器可以放在自己的机房，也可以托管在服务商，但网络、账号和硬件资源不与其他组织混用。政府、金融和持有强监管数据的团队更常采用这种部署，因为访问边界和审计要掌握在自己手里。

相对公有云，私有云更容易按内部规范改网络和镜像，资源不与外部客户共享；相对传统的逐台申请物理机，它仍能在资源池里较快划出新实例。代价是资源池本身要有人运营。

没有哪一种部署适合所有系统。同一家公司可以让对外网站留在公有云，把核心账务留在私有云，再通过专线互通，这就是混合部署。选择取决于数据能否出域、峰值是否稳定、有没有人维护资源池。

## 资源之间的关系

- 云服务器是进程最终运行的地方。
- 专有网络（VPC）给一批云服务器划出隔离的地址空间。
- 每台云服务器至少属于一个 VPC 里的子网。
- 安全组是实例网卡上的访问控制，决定哪些地址和端口能进来、能出去。
- 公网地址或负载均衡让 VPC 以外的客户端能够访问。
- 没有公网地址时，也可以用堡垒机或端口转发进到内网实例。

## 控制台里真正要做的两件事

1. 开一台按量计费的实例，确认停机或释放后不再继续扣费。包年包月适合长期存在的控制面，实验节点用按量更合适。
2. 先建 VPC，再把多台实例放进同一 VPC 的子网。后面组集群时，节点要能用内网地址互相访问。

只开了公网、没有放进同一 VPC 的两台机器，内网地址互相不通，Kubernetes 的节点通信也会失败。

## 安全组与内网地址

安全组按有状态规则放行端口。集群场景里，节点之间的控制面端口、CNI 使用的端口要在组内放行；对公网只打开需要的 22 或业务入口。不要为了省事对 `0.0.0.0/0` 开放全部端口。

同一 VPC 内，节点用内网地址通信。流量不出公网网卡，不按公网带宽计费，延迟也更稳定。kubelet 注册用的地址、etcd 对等地址都应写内网地址，公网地址只留给运维入口。

## VPC 与子网

VPC 是一块私有地址空间。例如规划 `10.16.0.0/16`，可用地址从 `10.16.0.1` 到 `10.16.255.254`，两头的网络地址和广播地址留出来，总数约 65534 个。这个空间只是编号范围，真正能分配给云服务器的是其中的子网。

在 VPC 下面再建子网，相当于把大网段切开。子网 `10.16.8.0/24` 去掉网络地址和广播地址后，大约有 254 个地址，可以放实验用的控制面和工作节点。另一个可用区若需要延伸，再建 `10.16.9.0/24`，两段都落在同一个 `10.16.0.0/16` 里，路由默认互通。

不同 VPC 之间默认不通过内网互通，即使地址碰巧写成同一段也不行。隔离由平台在网络层完成，不是靠两边防火墙碰巧拦截。需要互通时再显式做对等连接，并检查两边路由表，避免和云服务器所在的网段冲突。

## 常见问题

- 安全组放行了 22，但实例没有公网地址，公网 SSH 仍会超时。
- 两台机器分属不同 VPC，内网 ping 不通，集群脚本会在节点发现阶段失败。
- `/16` 是编号容量，不是已经可用的地址；没建子网之前无法把实例放进去。
