# 操作系统

## 并发和并行

并发说的是一段时间内有多件事都在推进，并不要求同一瞬间真的有多颗核心同时动手。单核机器把时间切成小片，进程轮流上场，人看起来像同时在做。

并行说的是同一瞬间有多条指令在不同的执行单元上各自往下走。两个人各拿一把铲子挖坑，一个小时能得到两个坑，这是并行。两个人共用一把铲子轮流挖，一个小时仍是两个较浅的坑，这是并发。

并行依赖多核或多处理器。并发在单核和多核上都能存在：单核上的并发是快速切换制造出来的同时感。程序要真正同时做多件事，才谈得上并行；只要求“看起来一起做”，并发就够了。

## 操作系统在管什么

- 进程：创建、撤销、调度、同步
- 内存：让有限的物理内存服务更多进程，并缩短平均访问时间
- 文件：把磁盘块组织成命名对象
- 设备：把具体硬件藏在统一接口后面，应用程序不直接碰端口号

用户态和内核态分开，是为了把不可信的程序挡在特权指令外面。

- 用户程序跑在用户态，弄坏自己的地址空间不应直接弄坏内核
- 停机、改页表、清中断这一类指令只允许在内核态执行
- 直接读写设备也算特权操作，避免进程绕过文件系统乱写磁盘
- 定时中断让内核能把 CPU 从某个进程手里拿回来，否则一个死循环就能占住机器

## 进程和线程差在哪

进程是程序针对一组数据的一次执行，是分配资源时的基本颗粒。早期要在一个服务里同时做几件小事，只能再创建一个进程，于是地址空间、文件表都被复制一份，既浪费也慢。后来把“被调度的那条执行流”单独拿出来，这就是线程。

相同点：在很多系统里，线程和进程一起竞争 CPU。Linux 早期甚至用进程那套结构来表示线程，2.6 之后调度实体才逐渐分开，但线程仍然是一个可被调度的任务。

不同点：进程之间互不依赖，一个退出不会带走别的进程。线程挂在某个进程上，进程一旦消失，它的线程全部失去地址空间。某个线程若调用了会结束整个进程的 `exit`，同进程的其它线程也会一起结束；普通的线程返回通常只结束自己。

实现上，`fork` 会让新进程得到父进程资源的一份拷贝，现代内核用写时复制把真正的拷贝推迟到第一次写入。创建线程的 `clone` 可以指定共享地址空间、文件表，只留独立的栈和寄存器。辈分也不一样：进程有严格的父子关系；同一进程里后创建的线程，共享的仍是这个进程的资源，不存在“线程的子进程式隔离”。

### 内核线程、轻量级进程、用户线程

内核线程由内核自己创建，用来跑刷新、中断下半部这类内核工作，不必绑在某个用户进程上。它使用内核栈，切换时不用换用户页表，所以比两个用户进程之间的切换便宜。

轻量级进程是内核看得见、又能调度的用户执行流。每个轻量级进程绑定一个内核调度实体，绑定在它的整个生命周期里都有效。同一进程中的多个轻量级进程共享地址空间，但各自有程序计数器、寄存器、用户栈和内核栈，因此可以同时落到不同的核上。

用户线程由线程库在用户态维护。内核只看见底下那个进程或轻量级进程。库可以自己决定下一个跑哪条用户线程，创建和切换都不必陷入内核。代价是：整个进程被抢占时，它的全部用户线程一起停；某条用户线程做了阻塞型系统调用，若底下只有一个轻量级进程，其它用户线程也会被拖住。

Linux 里每个可调度任务都有 `task_struct`，所以进程和线程能进同一个调度器。独占全部资源的任务像传统进程；和其他任务共享地址空间的就是轻量级进程。`clone` 创建的是内核可见的轻量级进程。`pthread_create` 在一对一实现里最终也会走到 `clone`，在纯用户线程库里则只是在用户空间登记一条新线程。

### PCB

进程控制块是内核认识一个进程的唯一凭据。里面记下标识、寄存器现场、调度参数、打开的文件和内存描述。进程切换时保存的就是这块结构加上硬件寄存器。没有 PCB，内核就无从知道这个进程停在哪条指令。

### 进程和程序

程序是放在磁盘上的指令和静态数据，可以长期存在。进程是一次执行，除了代码和数据，还有栈、堆和 PCB，执行结束就消失。同一份程序可以对应多个进程，例如同时开两个文本编辑器。

## 进程之间怎样交换数据

按用途粗分：

- 共享存储：双方都能读写同一块区域，吞吐高，要自己解决互斥
- 消息：每次搬运的数据少，要经过内核转发，延迟更明显
- 间接传递：消息先放进一个有编号的信箱，只有共享这个信箱的进程才能取走

再按机制分：

- 共享存储又分两种。基于固定数据结构的共享比较慢，格式受限制。基于一整段存储区的共享由进程自己解释字节，灵活，属于更常用的做法
- 管道在内存里放一段固定缓冲，同一时刻只适合一个方向，读写双方互斥。缓冲写满时写者等待，读空时读者等待。匿名管道里的数据读走就没有了，所以通常只有一个读端
- 消息可以直接挂到对方的接收队列，每个进程有自己的队列，消息要带上来源和长度。也可以先挂到中间信箱，发送方不必知道对方的进程号

## 为什么要有线程

进程同时承担“拥有资源”和“被调度”两件事，切换时包袱太重。把两件事拆开：进程继续作为申请内存和文件的单位，不必频繁创建；线程作为排队上 CPU 的单位，切换时少搬东西。

线程不单独占有地址空间，只保留运行所必需的线程控制块、程序计数器、寄存器和栈，其余资源与同进程的线程一起用。

### 和进程对照

1. 分配内存、文件和虚拟地址空间时数的是进程。线程不另要一套地址空间。
2. 不同进程的虚拟地址彼此隔离。同一进程的线程看到的是同一套地址。
3. 换进程要保存资源指针并切换页表。换线程不动这套地址映射，所以更快。
4. 进程切换一定进内核。线程切换可以在内核做，也可以由用户库在自己的线程表里做。
5. 进程能再创建进程，线程也能再创建线程。
6. 两者都有创建、运行、结束这几个阶段，只是结束时波及的范围不同。

### 线程模型

- 多对一：多条用户线程压在一个内核调度实体上。切换快，但一条线程阻塞就全停，也上不了多核
- 一对一：每条用户线程对应一个内核实体，可以真正并行，线程多了内核开销跟着涨
- 多对多：若干用户线程映射到较少的内核实体上，试图兼顾前两者。实现复杂，现在少见

## 进程同步

多个进程的结果互相依赖时，要约束它们经过关键点的次序。保证这种次序的机制就是同步。

若只是抢同一份资源，最后结果随谁先运行而变化，这叫竞争。办法是互斥：一个进程正在改共享变量或文件时，其它进程不能做同一件事。

能正确实现互斥，至少要满足：

1. 临界区里同时最多一个进程
2. 算法不能偷偷假设 CPU 有多快、有几颗
3. 没进临界区的进程，不得挡住别人进入
4. 想进临界区的进程不能永远等下去

### 靠忙等的互斥

1. 关中断。进程一进临界区就屏蔽中断，这样自己不会被换下。忘记开中断，整台机器的调度都会停。多核上关的是本地中断，别的核照样能进同一段代码
2. 锁变量。用一个全局 0/1 表示有没有人在里面。检查和改写如果不是原子的，两个进程会同时读到 0，然后都走进去
3. 严格轮换。用一个轮到谁的变量，进程不停地测试。这种空转叫忙等。等待时间极短时，忙等的锁称为自旋锁，因为它省掉了睡眠和唤醒。轮换法的问题是：该自己进却暂时不想进时，会挡住另一个真正想进的进程，破坏了上面的第 3 条

### 睡眠和唤醒

生产者往缓冲区放数据，消费者取走。缓冲区空时消费者不应空转，而应睡觉；生产者放入之后再叫醒它。对称地，缓冲区满时生产者睡觉。睡觉和叫醒如果和检查条件拆成两步，可能丢唤醒：消费者刚判断为“空”，还没睡觉就被换下，生产者放入并叫醒（此时没人睡），消费者再睡下就再也醒不来。

### 信号量

信号量把“检查计数”和“改计数、必要时睡觉”收成不可分割的一步。在这一步完成或进程已经挂到等待队列之前，别的进程动不了这把信号量。`P` 把计数减一，减完为负就睡；`V` 加一，有人等就叫醒一个。

### 管程

信号量散落在各个进程的代码里，漏一次 `V` 很难查。管程把共享变量和操作它的过程包在一起，编译器或运行时保证同一时刻只有一个进程在管程内执行。条件不对时，进程在条件变量上等待并暂时离开管程，让别人进去改条件，改完再发信号叫醒。

### 三个经典问题

- 生产者和消费者：空位和货物各用一个计数，互斥锁保护缓冲区本身。等待必须放在互斥之外，否则会先抱着锁睡觉
- 哲学家就餐：每人先拿一侧筷子再拿另一侧会成环。可以限制同时就座的人数，或规定奇数号先拿左、偶数号先拿右，保证至少有人能拿到两根
- 读者和写者：写者之间、写者与读者之间互斥；读者之间可以并行。若读者源源不断，写者可能饿死，所以要在协议里让新读者在写者到达后让路

## CPU 调度

调度要同时照顾几件事：

- 处理器尽量有事做，它是最贵的资源
- 每个进程都能分到合理的时间，不能有人永远轮不到
- 磁盘、CPU 等资源的忙闲不要长期偏在一头
- 已经定下的策略，即使让某个作业变慢，也要执行

### 作业

作业比一段程序更大，通常还带数据和一份说明，系统按说明决定怎么运行它。作业进系统后经历收容、运行、完成：先在后备队列里等，再变成进程真正执行，结束后进入完成状态，释放资源。

### 抢占还是不抢占

划分标准是：进程没阻塞、也没结束时，CPU 能不能被拿走。

- 非抢占：分到 CPU 就一直跑，直到它自己结束或阻塞
- 抢占：按优先级、剩余时间或时间片，把 CPU 分给别人

### 什么时候要做决定

- 刚 `fork` 完，父和子谁先跑
- 有进程退出，必须另选一个
- 进程等 IO 或等信号量，CPU 空出来
- IO 完成打断了当前进程，可能有更合适的进程变成就绪

### 批处理系统里

- 先来先服务：实现简单，短作业可能被长作业挡很久
- 短作业优先：平均等待时间往往更小，长作业可能一直被插队
- 最短剩余时间优先：新来的作业若比当前剩下的时间更短，就换上。短作业响应好，估计不准或不断来更短的作业时，长作业会饥饿

### 交互系统里

- 时间片轮转：就绪队列按片转动。片太短，切换开销占比高；片太长，交互会觉得卡
- 优先级：每个时钟嘀嗒可以把当前进程的优先级略降，防止它一直占着。优先级可以一开始写死，也可以随等待时间变化。非抢占的静态优先级只在当前进程让出时才重选；抢占式则在更高优先级到达时立刻换
- 多级反馈队列：新进程进最高一级，用完时间片就降级。交互型进程经常阻塞，留在高优先级；算很久的进程沉到大时间片的队列里
- 保证调度：记下每个进程自创建以来用过的 CPU 时间，优先补给用得少的
- 公平分享：保证调度对进程公平，对用户不一定公平。一个用户开很多进程就能拿走更多时间。公平分享按用户记账，再在用户内部分给进程
- 彩票调度：优先级高的进程持有更多彩票，每次开奖随机抽一张。长期比例接近票数比例，又避免绝对的先后顺序把低优先级永远排在后面

## 内存

### 没有抽象的年代

程序里写死物理地址。两份相同的程序不能同时进内存，因为它们要的地址重叠。

### 地址空间

每个进程看到的是自己的一套地址，和别人无关。硬件用基址寄存器加界限寄存器做动态重定位：访问的地址先加基址，再检查有没有越过界限。这样程序可以装到内存里的任意位置，也不会踩出自己的范围。

### 交换

内存放不下全部进程时：

- 整段交换：把一个进程完整挪到磁盘，腾出的物理内存给别人，之后再整段换回来
- 虚拟内存：进程只把正在用的那几页留在内存里
- 换进换出会在物理内存里留下大小不一的空洞，靠紧缩把空闲块拼起来很贵
- 栈和堆还会长大，分配时要给这种增长留余地

### 空闲块怎么记账

- 位图：每一位代表固定大小的分配单元。单元越小，位图越大；要找连续的 N 个空闲单元，得扫描位图
- 链表：空闲块和已占用块串成链。进程结束或被换出时把相邻空闲块合并。下次适配从上次停下的位置继续找，避免每次都从链头啃掉小块。最佳适配找最小的够用块，碎片更碎，搜索也更慢

### 虚拟内存

虚拟存储把进程的完整映像放在辅存，执行时只调入要用的部分。物理内存不够时，按页面置换或分区淘汰挑牺牲品。

虚拟地址切成等长的页，物理内存切成等长的页框。内存管理单元负责把虚拟页号换成页框号。

逻辑地址可以看成页号在高位、页内偏移在低位。用页号查页表得到页框号，再拼上原偏移，就是物理地址。页表放在内存里，寄存器只保存页表的起始位置。

每次访存都先查页表，等于多一次内存访问。TLB 是页表的高速缓存，命中时不必再读内存里的页表项。

三种组织方式：

- 分页：页号加偏移，页长固定
- 分段：段号、段长、段内偏移，段长随逻辑单位变化
- 段页：先用段号找到这张段的页表，再用页号找页框，最后加偏移。没有块表时要三次访存：段表、页表、目标单元。把段号和页号一起放进 TLB 后，命中时可以直接得到页框

### 分页为什么出现

一个进程若必须占连续物理内存，装入时外部碎片会让“总量够、形状不够”。按页切开后，页框可以散落在各处，外碎片消失。定位不再能靠一个基址寄存器，必须查页表。页长固定也让页内碎片有上界：最坏情况下每一段只浪费不到一页。

### 局部性

1. 时间上：刚执行过的指令、刚碰过的数据，短时间内可能再被用到。循环是典型来源
2. 空间上：挨着当前地址的单元很快也会被访问。指令顺序存放，数组和结构体也成簇摆放

置换算法指望的就是这种局部性。没有局部性时，任何算法都会频繁缺页。

### 页表太大时

- 多级页表：高位页号再分级。大片没用到的虚拟区间不必分配下一级页表，避免把整张页表常驻内存
- 倒排页表：按物理页框建表，而不是按虚拟页建表。表的大小跟物理内存走。查找时对虚拟页号做散列，到对应槽里核对（虚拟页，页框）是否匹配

### 置换算法

- NRU：页表项里留访问位和修改位，定时把访问位清掉。优先换出没被访问、也没被修改的；其次是没被访问但改过的（换出要写回磁盘）；再次是访问过但没改的；最后才是又访问又改过的
- FIFO：先装入的先走。实现简单，可能把经常用的老页换掉
- 第二次机会：仍按到达顺序看队头，若访问位是 1，就清掉并把它送到队尾，像刚装入一样再给一次机会
- 时钟：把第二次机会做成环。指针扫到访问位为 0 的页就换掉；碰到 1 就改成 0 并继续往前
- LRU：换最久没被碰的页。真正的 LRU 要在每次访问时更新顺序，硬件成本高，可以用老化算法近似：每个时钟周期把计数右移，当前被访问的页把最高位置 1
- LFU：换访问次数最少的。历史计数会让“曾经很热、现在不用”的页一直赖着，需要定期衰减

### 页长的取舍

页小：页内碎片少，装入更精细，但页表项变多。页大：页表短，磁盘一次传输更多，浪费的页内碎片也更多。

### 分段

分页对程序员是透明的，人看到的地址和物理上的分页对不上。人更自然的看法是：代码、栈、堆各是一段，长度不同，也没有固定顺序。分段让地址由段号和段内偏移组成，段可以独立伸缩。

### 分段和分页的差别

1. 分页没有外部碎片，平均有约半页的内部碎片。分段没有页内那种固定浪费，但段与段之间会留下外部碎片
2. 页长统一，段长由逻辑内容决定
3. 分页把用户眼里的连续地址打散到物理页框。分段可以让用户眼里的一段对应一段连续区间
4. 分页时用户只给一个地址，硬件拆成页号和偏移。分段时编译器和链接器明确使用段号，程序员或工具链能知道每段的上限

## 文件

文件管理提供文件和目录，把磁道、扇区藏起来，并做权限检查。每个打开或存放的文件都有文件控制块，记录位置、大小和属性。

文件名长度在现代系统里可以到大约 255 个字符。目录是把名字映射到控制块的节点集合，查找文件要先查目录。

有的实现把目录项只留名字和指向控制块的指针，真正要读属性时再加载控制块，目录扫描会更轻。

### 磁盘块怎么挂到文件上

- 连续分配：实现直白，顺序读很快。删除后留下空洞，文件创建时往往就要声明最大长度
- 链式存放：块与块用指针相连，不要求占着连续区间，长度可以后补。随机读要沿指针逐块走，每块还得留出指针的位置
- 索引：把块号集中放在索引节点里。打开文件时才把索引读入内存，支持直接定位，没有外部碎片。很小的文件也要付索引块的开销，所以常用直接块加间接块的组合

### 目录项本身的存放

- 固定长度的目录项浪费在短文件名上
- 紧挨着放会在删除后留下空洞，需要紧缩或空闲链表
- 堆式管理灵活，但要额外的索引才能按名字查找

### 共享

- 硬链接：多个目录项指向同一个索引节点。删掉其中一个名字，节点的链接计数减一，计数归零才真正释放数据。只删“最初那个名字”并不会自动清掉其它链接
- 符号链接：另存一条路径。不增加目标的链接计数，目标删除后链接会悬空。每次打开都要再解析一次路径，多一次开销

## 输入输出

IO 子系统要管设备和它们的控制器，对上提供与具体型号无关的接口。应用程序使用逻辑设备名，内核在打开时绑定到物理设备。换一块磁盘，程序仍写同一个逻辑名。

驱动程序负责把控制器的差异藏住：把串行比特流拼成字节块，做必要的校验，再把数据放进主存能访问的缓冲。

### CPU 怎样碰到设备寄存器

- 独立的 IO 端口空间：每个控制寄存器有一个端口号，用专门的输入输出指令访问。普通的内存读写碰不到这些端口
- 内存映射：寄存器占一段物理地址，访问方式和内存一样。好处是不必另设特权的 IO 指令，任何能访问内存的指令都能操作寄存器，保护也交给页表。坏处是这段地址不能被缓存成普通内存，否则 CPU 看到的是过期的设备状态；总线上的每个内存引用，内存控制器和设备控制器都要判断是不是给自己的

### DMA

在 DMA 之前，批量数据要么由 CPU 循环读写（程序控制），要么每传一个字就进一次中断。两种都让 CPU 陷在搬运里。

DMA 控制器拿到“内存地址、设备、长度”之后自己搬，搬完再发一次中断。吞吐取决于内存和设备，而不是取决于 CPU 每条指令能搬多少。CPU 因此可以在传输期间去跑别的进程。一次 DMA 请求通常针对连续的块；不连续的多段还是要配多次，或使用支持分散收集的控制器。

## 死锁

一组进程里，每个都在等只能由这组中另一个进程造成的事件，这组进程就死锁了。典型情况是各自占着资源，等对方先放。

四个条件缺一不可：

- 互斥：资源要么空闲，要么只属于一个进程
- 占有并等待：手里有资源，同时还在申请
- 不可抢占：不能强行剥夺
- 环路等待：等待关系围成环

### 四种处理策略

- 鸵鸟：当作死锁很少发生，不做处理。单机桌面系统有时这么选，代价是一旦发生只能重启
- 检测并恢复
  - 每种资源只有一份时，在等待图上找环。深搜加回溯，或反复去掉没有等待的结点，剩下来的就在环里
  - 每种资源有多份时，用“总量、已分配、还需要”三组向量。能满足剩余需求的进程假定它会归还，看最后能否全部完成
  - 恢复手段：抢占资源、回滚到没申请该资源之前的检查点、或者撤销进程
- 避免：资源轨迹图上，进入某些区域之后虽然还没死锁，但已经无法保证以后不锁，这种状态叫不安全。银行家算法在每次分配前模拟“分出去再全部收回”，只有仍能让所有进程走完才真正分配
- 预防：直接拆掉四个条件之一
  - 互斥很难拆，打印机不能同时交给两个人。能改成假脱机的设备就不要让进程直接占有
  - 占有并等待：启动前一次拿齐，或者申请新资源前先放下手里的。一次拿齐会降低利用率，也可能让要得多的进程长期拿不到全套而饥饿
  - 不可抢占：申请被拒就主动放开已有资源，以后一起再要
  - 环路：给资源编号，只允许按编号递增申请。要小号资源时，必须先放开比它大的号

### 两阶段加锁

第一阶段只申请、不干活。全部锁到手才进入第二阶段做真正的读写，做完统一释放。第一阶段只要有一把没拿到，就把已经拿到的全部放开，从头再来。这样不会握着一部分锁去等另一部分。

### 通信死锁

没有资源环，但双方都在等对方的报文，协议又没有超时，也会永远停住。给等待加上超时并重试，环就拆得开。超时太短会误伤慢请求，需要配合幂等。

### 活锁

双方都肯让，却让得一样整齐：都发现冲突、都退回、都在下一毫秒重试，系统不阻塞，也没有进展。随机退避可以打乱这种同步。

### 饥饿

进程没有被死锁卡住，却永远排在别人后面，例如优先级一直最低。调度上要有老化：等得越久，优先级越高。

# 操作系统

下面把进程、内存、文件、IO 和死锁再按面试里常见的问法收一遍。和上一半是同一套概念，侧重点放在生命周期和接口。

## 进程与线程

### 进程从哪来

- 系统启动时创建若干系统进程
- 正在运行的进程调用创建接口
- 用户请求打开一个程序
- 批处理系统取出一个后备作业并为之建进程

### 进程怎么结束

- 任务做完，主动退出
- 发现可处理的错误，主动退出
- 非法访问之类的严重错误，被内核终止
- 被别的进程请求终止

### 三种状态

运行、就绪、阻塞。运行中的进程用完时间片后回到就绪，不是回到阻塞。只有等某个事件时才进入阻塞；事件到来后回到就绪，是否马上运行还要再调度。

### 进程里面有什么

代码、已初始化数据、堆、栈，加上 PCB。PCB 里既有用户可见的标识，也有内核用的调度和内存信息，还有保存下来的寄存器。

### 切换时做哪些事

- 把当前寄存器写进旧进程的 PCB
- 装入新进程 PCB 里的寄存器
- 使地址相关的缓存与新页表一致
- 换上新进程的地址映射

### 父进程和子进程

`fork` 之后，子进程得到父进程用户空间的一份拷贝，包括代码、数据、堆、共享库映射和用户栈，但这份拷贝随后独立演化。父进程打开的文件描述符也会复制一份，所以子进程能接着读同一个文件。两边最明显的差别是进程号不同。写时复制让“看起来拷贝了”在真正写入之前几乎不占新的物理页。

### 僵死进程

子进程结束后，内核保留它的退出状态，直到父进程来取。这段时间里它是僵死进程：不跑了，但进程表项还在。父进程若自己先结束而没来收取，子进程会被挂到 init（或各发行版里的等效领养进程）名下，由领养者收取，避免进程表被占满。

### fork 和 execve

`fork` 创建子进程，并在父、子里各返回一次：父进程得到子进程号，子进程得到 0。`execve` 在当前进程的地址空间里换上另一个程序，成功时不会返回到原来的代码。常见组合是子进程 `fork` 之后立刻 `execve`，父进程继续做自己的事。

上下文是让程序能接着跑的全部状态：内存里的代码和数据、栈、通用寄存器、程序计数器、环境变量和打开的文件描述符。线程有自己的上下文子集：线程号、栈、栈指针、程序计数器和寄存器。同一进程的线程共享其余部分，包括代码、可写数据、堆和共享库，也共享已打开的文件。

### 线程从创建到回收

`pthread_create` 登记一条新线程，可以拿到线程号，并指定它去执行的函数和参数。

线程结束的几种方式：

- 线程函数返回
- 自己调用 `pthread_exit`。主线程若调用它，进程不一定马上结束，其它线程还能继续；主线程若从 `main` 返回，效果更接近整个进程退出
- 任意线程调用进程级的 `exit`，所有线程一起结束
- 别的线程用 `pthread_cancel` 请求取消它

`pthread_join` 等待指定线程结束并取走返回值，同时回收它的资源。不 join 又不分离，线程结束后会留下类似僵死的记录。

新建线程默认还能被别的线程等待并取回返回值。调用 `pthread_detach` 之后，结束时由运行库自行回收，不能再执行 join。

### 信号

信号是发给进程的短通知，用来报告异常、请求终止，或由内核在终端上产生（例如 Ctrl+C 发给前台进程组）。已经发出、还没被处理的叫待处理信号。常规信号在待处理期间同类只留一份，多出来的会被合并掉，所以不能用信号个数精确计数。

### 线程再从设计动机看

希望多条执行流并发，又不想为每一条复制整个地址空间。资源仍记在进程上，调度记在线程上。线程自己的部分是程序计数器、寄存器、栈和状态；地址空间是借进程的。

纯用户态实现把线程表放在用户空间，调度算法可以自己定，但一个线程做阻塞 IO 会让整个进程睡住，不主动让出 CPU 时其它线程也得不到运行。内核态实现把线程表放在内核，调度和阻塞由内核处理，常用线程池复用内核实体，避免反复创建。

### 轻量级进程

和普通进程比，轻量级进程共享绝大部分地址空间和系统资源，却仍有自己的进程号，也可以有父子关系。它留下的上下文只够调度器使用，所以比完整进程轻，又比纯用户线程能上多核。

### 用户线程相对内核线程

1. 可移植：纯用户线程库不太依赖具体内核
2. 扩展：用户库好改，内核线程模型受内核版本限制
3. 性能：用户线程用不上多核；内核线程可以。用户线程一条阻塞全部停住，内核线程不会
4. 编程：用户线程的调度和异步要自己处理，内核线程多半只调创建和同步接口

### Linux 的选择

Linux 采用一对一：一条线程对应一个轻量级进程，由内核调度。同步、取消等策略放在核外的线程库。历史上的 LinuxThreads 还会为每个进程准备管理线程，处理一些信号和回收事务；NPTL 之后这套管理方式已经不同，但“内核调度、库负责 API”这个分工还在。

### 进程和线程再对照一次

- 资源记在进程上，线程只是在这份资源里运行
- 进程之间地址空间不同，线程之间相同
- 换进程要动页表和资源指针，换线程主要换寄存器和栈
- 进程调度一定在内核完成；线程要看它是内核可见的还是纯用户态的

## 进程间通信

要回答三件事：数据怎么交到对方手里，临界区会不会交叉，次序是否符合预期。

同步指合作的进程在关键点上互相等待或互相通知。竞争指共享数据的最终值取决于操作次序。互斥用来保证使用共享资源时别人不能做同一操作。

互斥的四条要求与前面相同：临界区互斥、不假设 CPU 速度和数量、区外进程不得挡人、等待必须能结束。

忙等方案里，关中断在多核上只影响本核，忘了恢复则系统异常；单纯的锁变量因检查和赋值不原子而失效；严格轮换会让“轮到但暂时不想进”的一方挡住另一方。

信号量把进入临界区的名额做成计数。申请失败就在这个信号量上睡眠，释放时再叫醒一个。管程则把共享数据和操作封起来，并用条件变量上的等待和发信号替换散落各处的计数操作。管道也是一种现成的同步：空则读者停，满则写者停。

### 常见机制

1. 匿名管道：半双工，数据单向流动，以内核缓冲的形式存在，一般要求有亲缘关系
2. 命名管道：放在文件系统的路径上，没有亲缘关系的进程也能打开，仍按先入先出、字节流来用
3. 信号量：控制能有几个进程同时碰共享资源，常当锁来用
4. 消息队列：带边界的消息链表，存在内核里，直到重启或被显式删除。比信号能带的数据多，也比管道更有消息边界
5. 信号：通知“某事件发生了”，不适合传大块数据
6. 共享内存：把同一段物理页映射进各方的虚拟地址。最快，因为少了拷贝。必须另配信号量一类的同步，否则并发写会把数据搅乱
7. 套接字：能跨设备。本机也可用 Unix 域套接字，内核仍然要拷贝，除非再配共享内存

共享内存去掉了消息队列那种用户态与内核态之间的反复拷贝，同时把互斥问题交还给应用。

### 线程之间

1. 互斥锁、读写锁、条件变量。只有拿到互斥锁的线程能改那份公共结构。读写锁让读者并行、写者独占。条件变量在条件不成立时原子地放锁并睡眠，被叫醒后要重新检查条件
2. 信号量：有无名的，也有可在进程间使用的命名信号量
3. 信号：和进程间的信号类似，用来通知而不是交换大块数据

线程已经共享地址空间，所以不必再为“把字节搬过去”单独设计一套机制。

## 怎样从用户态进到内核态

1. 系统调用。进程主动请求内核服务。`fork` 就是这样一次请求。x86 历史上常通过 `int 0x80` 或更新的 `syscall` 指令进入内核
2. 异常。例如缺页、除零。这些不是进程事先安排的调用，内核仍要接手
3. 外设中断。磁盘完成、网卡收包都会打断当前指令。若当时在用户态，这条路径同样进入内核

## 调度

需要重新选择进程的时机：新进程诞生、当前进程退出、当前进程阻塞、IO 中断到来、时钟中断到来。

算法和前半部分对应：

- 先来先服务，用队列即可
- 短作业优先，要用能按估计时间取最小值的结构
- 最短剩余时间优先，是短作业优先的抢占版
- 优先级，分静态和动态
- 多级反馈，各级时间片可以按 2 的幂变长
- 保证调度，跟踪已使用时间
- 彩票调度，票多的被抽中的概率高

## 存储

多个程序同时在内存里，要解决两件事：互相不能越界，以及程序不能依赖自己被装到哪个物理地址。这就是保护和重定位。

交换把整个进程搬进搬出，会制造空洞。记账可以用位图或链表。位图在内存很大时本身就很大。链表上的首次适配找第一个够用的块，最佳适配找最贴合的块，后者常要走完一条链。

虚拟地址由内存管理单元翻译。一页对应一个页框。虚拟地址拆成页号和偏移，页号去页表里查，还要看这一页现在在不在内存。页表项里通常还有访问位、修改位和权限位。

TLB 解决“页表在内存里、映射太慢”的问题，等于给页表做缓存。多级页表用高位分段索引下一级，避免空区域占用整张表。倒排页表按页框数做散列表，从虚拟页号散列到可能的槽。

置换算法的关系：

- NRU 用访问位和修改位分四类，并定期清访问位
- FIFO 按进入顺序
- 第二次机会在 FIFO 上给访问过的页一次“改标志、重新排队”
- 时钟用环形指针实现第二次机会
- LRU 可用老化或“链表加散列表”近似
- LFU 按频率，注意老热点的计数要能衰减

分段是按逻辑把地址空间拆开，代码段和栈段各自增长。它回答“地址在逻辑上怎么划”，分页回答“逻辑地址怎么落到物理页框”。两者可以叠在段页式里。

## 文件系统

命名：长度上限大约 255。Windows 的文件名默认不区分大小写，Linux 区分。

结构上，文件可以是字节流，也可以是定长记录，少数系统用树状记录。目录则从单层发展到两层，再发展到多层。单层难以避免重名。两层按用户分开，缓解重名，也便于做保护和共享。多层允许目录里再放目录，形成今天的路径。

空间分配：

- 顺序存放利于顺序和直接访问，但有外部碎片，长度常常要预先知道
- 指针成链时不要求连续区间，随机读要逐块跳跃，指针本身还占空间
- 索引节点把块号集中起来，打开时读入，支持直接访问。节点本身要占空间

共享要么多个目录项指向同一索引节点（硬链接），要么另存路径（符号链接）。

## IO

块设备以固定大小的块为单位，每块有地址，可独立读写。字符设备按字节流前进，不能按块号寻道，键盘是典型。

轮询由 CPU 不断问设备“好了没有”，干预太密。中断改为设备完成后通知 CPU，CPU 再把一个字或一块小缓冲拷进内存，然后回去做别的事。连接数一多，若每个连接一个线程阻塞着读，线程数量和切换都会爆。多路复用让一个线程同时等许多描述符，某个就绪再去读写。它仍是同步的：数据要由这个线程自己从内核缓冲拷走。并发粒度变小之后，代码要自己维护每个连接的状态。

DMA 在大数据块上再减一次干预：CPU 只下命令，控制器写内存，全部完成后只来一次中断。优点是 CPU 介入更少，搬运不必再绕 CPU 寄存器。限制是一次命令通常对应一段连续块，零散的小 IO 并不划算。

控制器还要把串行比特流拼成字节并做校验。CPU 访问控制器，要么走独立端口和专门指令，要么把寄存器映射进内存地址，用页表限制用户进程直接碰到它们。

## 五种 IO 模型

1. 同步阻塞：调用读之后，进程一直睡到数据进了用户缓冲。期间什么都不做
2. 同步非阻塞：缓冲还没有数据时立刻返回错误，调用方稍后重试。不阻塞，但要反复问
3. 多路复用：把阻塞从“读某个连接”挪到 `select` / `poll` / `epoll` 上。仍要在返回之后自己把数据读走，所以还是同步 IO，只是能用一个线程盯很多连接
4. 信号驱动：先登记，数据到达时用信号通知，再由进程来读。等待阶段进程可以做别的事
5. 异步 IO：内核把数据准备好并放到用户指定的缓冲之后才通知。进程收到通知时拷贝已经完成。这需要内核提供真正的异步接口，不是把非阻塞读套一层循环

## 死锁

定义仍然是：每个进程都在等一个只能由组内其它进程引发的事件。四个条件是互斥、占有并等待、不可抢占、环路等待。

检测：单份资源在等待图里找环；多份资源用矩阵模拟分配和释放。恢复靠抢占、回滚或结束进程。

避免：先区分安全与不安全。不安全只说明存在一种申请顺序会走进死锁，不是说已经死锁。银行家算法对单类资源和多类资源都是同一想法：假装分配，看剩余资源能否让每个进程按某种次序走完。

预防：

- 拆互斥往往不现实，打印机这类设备必须独占。能假脱机的就不要直接分配实物
- 拆占有并等待可以用“运行前拿齐全部资源”，副作用是资源利用率差，并且可能饥饿
- 拆不可抢占：新申请失败时，放开已经占有的，以后再一起申请
- 拆环路：资源编号，只按递增顺序申请

活锁是互相礼让却谁也不开始。饥饿是可以运行，但分配策略让它无限期靠后。

## 中断和系统调用

时钟中断来自硬件的定时脉冲，用来提醒内核时间片到了，从而有机会从用户态收回 CPU，并按中断类型做不同处理。中断源可以在 CPU 内部，例如执行了特权指令或时间片耗尽；也可以在外部，例如键盘。

系统调用是用户程序主动请求内核代劳的入口。改页表、直接碰设备都需要更高特权，普通指令做不到。进入内核靠一条专门的陷入指令，它只应由用户态发起。内核内部改调普通函数，不再走这条指令。

把这几段放在一起记：时钟中断保证内核能抢回 CPU，系统调用保证用户能安全地请求服务，缺页异常则把虚拟内存的按需调入接进同一条陷入内核的路径。调度、换页、驱动，最后都要经过这些入口才能发生。
