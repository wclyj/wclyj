# 进程之间与线程之间怎么通信

## 概念

进程是正在执行的程序，操作系统按进程分配地址空间、打开的文件和其它资源。一个进程里可以有多条执行流，每一条就是线程。线程才是被调度到 CPU 上运行的基本单位，它离不开所属进程提供的地址空间。

### 进程

进程拥有独立的资源。系统给每个进程分开的地址空间，一个进程出错，不会直接改写另一个进程的内存。只有一个进程在跑时，机器在同一段时间里只推进这一件事；多个进程交替运行时，可以一边播放音频，一边编译代码。单核上这两件事并不是同一瞬间都在执行，而是调度器快速切换，间隔短到人感觉它们同时在进行。

### 线程

线程是进程内部的一条执行流，CPU 时间片最终落在线程上。单线程程序只有一条路径，做完当前调用才会做下一件。多线程则在同一地址空间里开出多条路径。多线程通常不是把同一段计算变成“更快的单核速度”，而是让进程在等待磁盘或网络时，还有别的线程能占用 CPU，从而提高这段时间里的利用率。

谁先抢到 CPU 由调度器决定，线程本身不能假设自己会按创建顺序一直跑完。所以没有额外同步时，执行次序是不确定的。

### 获取线程的方式

在 Java 里常见四种来源：

- 实现 `Runnable`，任务没有返回值
- 实现 `Callable`，任务可以返回结果，并包在 `Future` 里
- 直接构造 `Thread`
- 从线程池提交任务，由池来创建或复用线程

前三种适合把线程模型看清楚；真正的服务里更常用池，避免无限制地新建线程。

## 进程通信方式

- 管道：半双工，字节只朝一个方向流。匿名管道只适合有亲缘关系的进程，常见是父进程在 `fork` 之前建好管道，子进程继承两端的文件描述符。
- 信号量：一个由内核维护的计数。进程进入共享资源前把计数减一，降到负数就睡眠。它用来互斥或限制并发人数，本身不搬运业务数据。
- 消息队列：内核里的一条消息链表，按队列标识访问。单条消息有边界，容量比无名管道的“无格式字节流”更清晰，也不要求进程有亲缘关系。
- 共享内存：一块被映射进多个进程地址空间的物理页。数据不用在用户态和内核态之间来回拷贝，所以吞吐最高。读写双方仍要用信号量或锁约定先后，否则会读到写了一半的内容。
- 套接字：同样可以在本机两个进程之间通信，也可以跨机器。其它几种方式一般限于同一台主机。

## 线程间的通信方式

线程天然共享进程的堆和全局数据，通信常常就是读写同一块内存，再靠同步原语避免踩踏。

- 锁
  - 互斥锁保证同一时刻只有一个线程改某段结构
  - 读写锁允许多个读者并行，写者与任何读者、写者互斥
  - 条件变量让线程在“条件还不成立”时原子地放开互斥锁并睡眠，条件成立后再被唤醒。检查条件必须放在持锁的区间里
- 信号量：有不带名字的进程内信号量，也有可以跨进程的命名信号量。线程里它同样用来表示“还剩几个名额”
- 信号：线程也能接收信号，但信号更适合通知“某件事发生了”，不适合像消息队列那样搬运一块数据。线程之间要交换数据，还是靠共享内存加同步

## 多线程省下的切换成本

切换进程时，要换掉的上下文包括用户地址空间、页表、内核栈和寄存器。同一进程里的线程切换，地址空间和页表可以留着，主要保存和恢复寄存器、栈指针、程序计数器这些线程私有状态，所以更轻。

进程各自有一套变量，改自己的堆不会影响别人，隔离更好，代价是通信要走内核提供的通道。线程共享数据，传一个指针就能让对方看见，写起来直接，也更容易把数据写坏。创建和销毁线程的开销在多数系统上也小于再 `fork` 出一个进程。

因此：计算彼此独立、又怕互相写坏内存时用多进程；需要频繁交换大块数据、且可以接受同一地址空间时用多线程。

## 让几条线程按预定次序打印

调度器不保证 `start` 的调用顺序就是运行顺序。下面三个线程各自打印一个字母，实际输出可能是任意排列。

```java
static void unordered() {
    Thread a = new Thread(() -> System.out.println("A"), "a");
    Thread b = new Thread(() -> System.out.println("B"), "b");
    Thread c = new Thread(() -> System.out.println("C"), "c");
    a.start();
    b.start();
    c.start();
}
```

某次运行可能打印：

```text
C
A
B
```

### 使用 join

`join` 让调用者等到目标线程结束。主线程按 a、b、c 的顺序启动，并在每一次启动后立刻等待，下一个线程就不会提前开始。

```java
static void inOrder() throws InterruptedException {
    Thread a = new Thread(() -> System.out.println("A"), "a");
    Thread b = new Thread(() -> System.out.println("B"), "b");
    Thread c = new Thread(() -> System.out.println("C"), "c");
    a.start();
    a.join();
    b.start();
    b.join();
    c.start();
    c.join();
}
```

输出固定为：

```text
A
B
C
```

`join()` 不带参数时，内部调用 `join(0)`。参数小于 0 会抛出非法参数；等于 0 表示不设超时。实现里在持有该线程对象锁的情况下循环：只要 `isAlive()` 仍为真，就 `wait(0)`。目标线程结束时会 `notifyAll`，主线程被唤醒后再看一次是否还活着，活着就继续等。

这里阻塞的是调用 `join` 的主线程，不是被等待的那个工作线程。a 还没结束时，主线程走不到 `b.start()`。

超时版本会用进入时的时间戳计算还要等多久，`wait` 返回后把已经过去的时间扣掉，剩余时间耗尽就离开循环，即便线程还活着。

### 利用 Executors 线程池

`Executors.newSingleThreadExecutor()` 给出一个只有一条工作线程的池。任务进的是 FIFO 队列，池里始终至多一个任务在跑。依次提交 a、b、c 时，a 先执行，b 和 c 留在队列里，前一个返回后才取下一个。

```java
static void pooled() {
    ExecutorService pool = Executors.newSingleThreadExecutor();
    pool.execute(() -> System.out.println("A"));
    pool.execute(() -> System.out.println("B"));
    pool.execute(() -> System.out.println("C"));
    pool.shutdown();
}
```

输出同样是 A、B、C。这靠的是队列顺序加上单线程，不是靠三个 `Thread` 自己协商。程序退出前要 `shutdown`，否则池里的非守护线程会把进程留住。

若三个任务必须并行、又要在某一点汇合，就不要用单线程池硬排顺序，改用 `CountDownLatch` 或 `CyclicBarrier` 表达“谁等谁”。
