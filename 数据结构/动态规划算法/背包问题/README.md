# 动态规划问题

这一篇仍是 0-1 背包，换一组重量和价值，把「为什么不能贪心」和「怎样从表格倒推选了谁」写清楚。

## 应用场景

背包最多装 6 个单位。三件礼物都不能拆开，也不能拿重复的一件：

| 物品 | 重量 | 价值 |
| ---- | ---- | ---- |
| 茶叶 | 2    | 5    |
| 杯子 | 3    | 7    |
| 茶壶 | 4    | 9    |

要价值最高，总重不得超过 6。

若按「价值除以重量」贪心，茶壶单位价值 2.25，杯子约 2.33，茶叶 2.5。先拿茶叶再拿杯子，价值 `5+7=12`，还剩 1 个单位。最优其实是茶叶加茶壶，价值 `5+9=14`。单位价值最高的组合并不是答案，所以这里用填表，不用贪心。

## 动态规划算法

### 概念

令每个阶段只比上一阶段多一件物品。阶段之间不独立：容量为 `c` 的答案要看「容量 `c`」和「容量 `c-重量`」两个更早的格子。表把这些重叠的子问题只算一次。

### 求解 0-1背包问题

每件物品进入决策时二选一。完全背包才允许一件物品在同一行里被加多次；把完全背包硬写成 0-1 会少算，把 0-1 写成同一行向左累加会多算。

### 主要思想

`f[i][c]` 是前 `i` 件、容量上限 `c` 的最优价值。

- 第 0 行、第 0 列全是 0。
- 新物品太重：抄上一行。
- 放得下：`f[i][c] = max(f[i-1][c], v[i] + f[i-1][c-w[i]])`。

### 思路推导图

| 物品 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| ---- | - | - | - | - | - | - | - |
| 无   | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| 茶叶 2/5 | 0 | 0 | 5 | 5 | 5 | 5 | 5 |
| 杯子 3/7 | 0 | 0 | 5 | 7 | 7 | 12 | 12 |
| 茶壶 4/9 | 0 | 0 | 5 | 7 | 9 | 12 | 14 |

容量 5、只考虑到杯子：不拿杯子是上一行的 5；拿杯子还剩容量 2，上面是 5，合计 12。容量 6、加入茶壶：不拿是 12；拿茶壶还剩 2，上面是 5，合计 14。14 更大。

容量 4、加入茶壶：不拿是 7（一杯子），拿茶壶是 9。这里单件茶壶胜过杯子，和容量 6 的组合不是同一种取舍。

## 代码实现

```python
def knapsack_plan(weight, worth, cap):
    """0-1 背包。返回最大价值，以及从轻到重决策顺序下被选中的下标。"""
    n = len(worth)
    f = [[0] * (cap + 1) for _ in range(n + 1)]
    pick = [[0] * (cap + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        for c in range(1, cap + 1):
            f[i][c] = f[i - 1][c]
            wi = weight[i - 1]
            if wi <= c:
                alt = worth[i - 1] + f[i - 1][c - wi]
                if alt > f[i][c]:
                    f[i][c] = alt
                    pick[i][c] = 1
    selected = []
    i, c = n, cap
    while i > 0 and c > 0:
        if pick[i][c] == 1:
            selected.append(i - 1)
            c -= weight[i - 1]
        i -= 1
    selected.reverse()
    return f[n][cap], selected
```

倒推：右下角 14 比正上方 12 大，说明茶壶被选了，容量减到 2。容量 2 那一列在杯子那一行没有打标（12 来自更左边的组合，不是这一列），再往上茶叶那一行容量 2 打了标，选中茶叶。清单是下标 0 和 2。

若从左到右扫整张 `pick`，会把容量 4 时「只拿茶壶」也打印出来，那不是最终方案。必须从最终容量往回跳。

### 复杂度

填表 `O(n·cap)`。只保留上一行可以把空间降到 `O(cap)`，但倒推具体方案时要么留下选择标记，要么保留整张价值表。滚动数组若从左往右更新，会把「同一件拿两次」算进去，所以压缩空间时容量必须从大到小扫。

### 边界

所有物品都重于容量：答案 0，标记全空，倒推不会减出负数。价值全 0 时最大价值是 0，任何子集都对，代码因为用「严格大于」而什么都不选，这是合法最优之一。
