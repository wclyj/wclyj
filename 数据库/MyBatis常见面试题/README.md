# MyBatis常见面试题

#### 1、`#{}` 和 `${}` 差在哪？

`${}` 做的是文本替换，映射文件解析阶段就把占位内容拼进 SQL 或标签属性。它适合表名、排序列这种不能当作预编译参数的位置，也适合从属性文件读出的驱动名一类配置。风险是拼接，值如果来自请求，就要自己保证没有注入。

`#{}` 是预编译参数。MyBatis 先把这里换成 `?`，执行前通过 `PreparedStatement` 按顺序绑定，字符串会按参数传递，而不是拼进 SQL 文本。`#{order.buyer}` 这类路径用反射（OGNL）从入参对象上取属性，等价于先拿到订单再取买家字段。

#### 2、映射文件里，除了增删改查四个标签，还会出现什么？

还有结果映射 `resultMap`、参数映射 `parameterMap`、可复用片段 `sql`、把片段嵌进来的 `include`，以及为不支持自增的库生成主键的 `selectKey`。

动态 SQL 还有一组标签：`if`、`choose`、`when`、`otherwise`、`trim`、`where`、`set`、`foreach`、`bind`。`sql` 只是片段，本身不执行；`include` 把它插到引用处。`parameterMap` 已经不推荐，新代码用方法参数和 `parameterType` 即可。

#### 3、一个映射文件配一个 Dao 接口，这个接口靠什么工作？方法能重载吗？

日常说的 Dao 接口就是 Mapper 接口。接口的全限定名必须等于映射文件的 `namespace`，方法名必须等于语句的 `id`，方法参数会传给这条 SQL。接口没有手写实现类。

调用时，MyBatis 用「全限定名 + 方法名」当键，找到唯一的 `MappedStatement`。例如 `app.dao.OrderDao.findByNo` 对应 namespace 为 `app.dao.OrderDao`、id 为 `findByNo` 的那条语句。每个 `select`、`insert`、`update`、`delete` 都会被解析成一个 `MappedStatement`。

方法不能重载。键里没有参数类型，两个同名方法会抢同一个 id。

运行时用 JDK 动态代理给接口生成代理。代理拦住方法调用，执行对应语句，再把结果返回。

#### 4、分页是怎么做的？插件靠什么改写 SQL？

框架自带 `RowBounds`，它是在结果集已经取回内存之后再截取一段，属于内存分页，数据量大时仍然会把前面的行读出来。

真正少扫磁盘，要在 SQL 里写上数据库认识的限制语法，或者用分页插件去改写语句。插件实现 MyBatis 的拦截接口，在语句即将执行时拿到原始 SQL，按方言补上物理分页。例如原来是 `select id, title from article`，改写后变成对子查询追加 `limit 20 offset 40`。页码和页大小作为新的绑定参数，而不是拼进文本。

#### 5、插件怎样跑起来？怎样自己写一个？

能拦截的对象只有四类：`Executor`、`StatementHandler`、`ParameterHandler`、`ResultSetHandler`。MyBatis 用 JDK 动态代理包住它们。被点名的方法被调用时，会进入插件的 `InvocationHandler`，也就是你实现的 `intercept`。没被点名的方法不会进插件。

写法是实现 `Interceptor`，在类上用注解标明要拦的接口和方法签名，再把插件类写进配置。漏掉配置的话，类在 classpath 里也不会生效。多个插件按配置顺序套成一层层代理，顺序会影响结果。

#### 6、批量插入能把数据库生成的主键收回来吗？

可以。JDBC 的 `Statement` 能在批处理之后通过 `getGeneratedKeys` 取回自增键，MyBatis 只是把这个能力暴露出来。需要在插入语句上声明使用生成键，并指定属性名。批量时返回的是一组键，顺序与添加批处理的顺序对应，不要假设数据库会按别的规则重排。

#### 7、动态 SQL 解决什么问题？执行时在算什么？

动态 SQL 让映射文件用标签做条件判断，按入参决定哪些片段进入最终语句，避免在 Java 里拼接字符串。标签就是上一题列出的那九个。

执行时用 OGNL 对入参求值。`if` 的 test 为真才保留其中的 SQL；`foreach` 展开集合；`where` 和 `set` 会顺手去掉多余的 `AND`、逗号。算完之后才得到一条固定 SQL，再进入预编译。动态发生在绑定参数之前，不是数据库引擎里的动态。

#### 8、查询结果怎样变成对象？有几种映射办法？

第一种是 `resultMap`，逐列写明列名和属性的对应关系，嵌套对象也在这里声明。

第二种靠列别名。属性叫 `buyerName` 时，SQL 写成 `buyer_name AS buyerName`。列名比较时不区分大小写，别名写成别的大小写仍能对上。没有下划线转驼峰的配置时，不要指望 `buyer_name` 会自动填进 `buyerName`。

有了对应关系之后，MyBatis 用反射构造对象，再按映射给属性赋值。对不上的列被忽略，对不上的属性保持默认值。构造器映射可以走带参构造，不依赖无参构造和 setter。

#### 9、一对一、一对多能查吗？两种写法差在哪里？

可以。多对一就是一对一的查询形状，只是「一」的那一侧在业务上被多行引用；多对多可以看成一对多再加一张中间表。接口方法返回单个对象还是列表，由你声明的返回类型决定。

关联数据有两种拿法。一种是嵌套查询：主查询先查出订单，关联的买家再用另一条 SQL 按外键去取，可能产生 N+1 次查询。另一种是嵌套结果：一条 JOIN 把订单列和买家列一起选出，在 `resultMap` 里把列分给两个对象。后者只有一次往返，但 JOIN 会让主表行在结果集里重复出现。

重复行怎样收成一个订单？靠 `resultMap` 里的 `id`。它标出唯一确定主对象的列，MyBatis 用这个列的值合并行。联合主键就写多个 `id`。关联对象若也会重复，同样靠它自己的 `id` 合并。

例如 JOIN 之后得到六行，订单号都是 9001，买家列相同，明细编号分别是 1 到 6。合并之后应是一张订单带六条明细，而不是六张重复的订单。

#### 10、支持延迟加载吗？原理是什么？

只对关联对象和关联集合生效，也就是一对一的 `association` 和一对多的 `collection`。全局开关是 `lazyLoadingEnabled`。也可以在单条关联上单独关闭。

实现上用代理包住主对象。访问 `order.getBuyer().getCity()` 时，拦截器发现买家还是空的占位，就发送事先准备好的那条按买家主键查询的 SQL，把结果 `set` 回去，再继续取城市。没被访问的关联不会发 SQL。

这和 Hibernate 的懒加载是同一类手法：先给一个代理，真正碰属性时再查。区别是 MyBatis 的懒加载 SQL 要你自己写在映射里。

#### 11、不同映射文件里，语句 id 可以相同吗？

配置了 `namespace` 就可以。没配置就不可以。现在的版本里 namespace 实际上已经是必需的，旧文档把它说成可选，是早期行为。

原因是语句登记在一张以字符串为键的表里，键是 namespace 加 id。没有 namespace 时键只剩 id，后解析的文件会覆盖先解析的。namespace 不同，即使 id 都叫 `findById` 也不会撞车。

#### 12、怎样做批处理？

使用 `ExecutorType.BATCH` 打开的 `SqlSession`，底层是 `BatchExecutor`。它把多次更新放进 JDBC 批处理，而不是每条都立刻发给服务器。查询不要指望批处理，JDBC 的批处理针对更新。

#### 13、有几种 Executor？差别是什么？

三种：

- `SimpleExecutor`：每次查询或更新都新建一个 `Statement`，用完就关
- `ReuseExecutor`：以 SQL 文本为键缓存 `Statement`。同样的文本再次执行就复用，不立刻关闭，从而少一次准备语句的开销
- `BatchExecutor`：只服务更新。调用时 `addBatch`，等到刷新或提交才 `executeBatch`。它会按 SQL 分桶，持有多个 `Statement`

这些缓存和未发送的批处理都只活在当前 `SqlSession` 里。会话一关，未刷出的批处理如果没提交，行为要看你是否显式 `flushStatements`，不要假设关闭时一定会替你执行。

#### 14、怎样指定用哪一种执行器？

配置文件里的 `defaultExecutorType` 决定工厂默认创建哪一种，取值是 `SIMPLE`、`REUSE`、`BATCH`。也可以在 `openSession` 时传入 `ExecutorType`，单次会话覆盖默认值。分页或插件若依赖执行器类型，要和这里一起看。

#### 15、能映射枚举吗？

能。枚举只是特例，任何 Java 类型都可以映射到一列，只要提供 `TypeHandler`。实现 `setParameter` 和 `getResult`：前者把 Java 值绑到 `?`，后者把列值变回 Java 值。枚举常见的做法是存 `name()` 或自定义的整型编码，不要依赖枚举声明顺序，因为调整常量次序会改掉 `ordinal()`。

#### 16、被 include 的片段必须写在引用它的语句前面吗？

不必。解析虽然按文档顺序往下走，但语句若引用了尚未出现的片段，会先被标成未完成，等全部标签扫过之后再解析第二遍。第二遍时片段已经登记，语句就能补全。所以片段可以放在文件末尾，甚至通过 `include` 引用其他 namespace 里已经定义的片段。

#### 17、映射文件和内部对象怎样对应？

全部配置最后都进 `Configuration`。`parameterMap` 变成 `ParameterMap`，其中每一项是 `ParameterMapping`。`resultMap` 变成 `ResultMap`，其中每一项是 `ResultMapping`。四类语句标签变成 `MappedStatement`。语句在运行前再结合入参生成 `BoundSql`，里面是替换好动态片段之后的 SQL，以及按出现顺序排好的参数映射。

#### 18、为什么把它叫半自动 ORM？和全自动差在哪？

Hibernate 这类工具按实体关系自己生成 SQL，加载关联时可以根据映射直接取，调用方不写语句，所以常被叫全自动。MyBatis 的 SQL 由人写在映射文件里，关联查什么、怎么 JOIN，都要显式给出，框架负责绑定参数、映射结果、管理会话，所以叫半自动。

代价是 SQL 可控，复杂报表不容易被生成器写坏；好处没了「改一个字段、所有查询自动跟上」的省事，列变更要自己改映射。
