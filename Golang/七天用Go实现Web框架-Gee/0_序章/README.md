# 序章：为什么要自己写一个 Web 框架

## 来源

这篇是七日实现 Gee 的开篇。原始连载地址不在笔记中重复，下面只保留设计问题和目录。

## 设计一个框架

做 Web 应用时，第一反应往往是选框架。框架之间差别很大。Python 里 Django 功能全，Flask 保持小。Go 这边同样不断出现新框架，例如 Beego、Gin、Iris。标准库明明能监听端口，为什么还要框架？动手之前先回答：框架到底替我们消掉了哪类重复劳动。

先看 `net/http` 怎么接一个请求：

```go
func main() {
    http.HandleFunc("/", showPath)
    http.HandleFunc("/hits", showHits)
    log.Fatal(http.ListenAndServe("127.0.0.1:8000", nil))
}

func showPath(w http.ResponseWriter, r *http.Request) {
    fmt.Fprintf(w, "path = %q\n", r.URL.Path)
}
```

标准库负责听端口、登记静态路径、解析报文。下面这些日常需求它不打包：

- 动态路径，例如 `/hello/:name` 或 `/assets/*filepath`
- 按路由分组做统一鉴权，而不是每个处理函数各写一遍
- 一套省事的 HTML 模板入口

离开框架就得反复手写的地方，就是框架的价值。但不是每一处重复都该塞进框架。Python 的 Bottle 把整个微框架放在单个 `bottle.py` 里，大约四千多行。看它提供什么，就能抓住核心：

- 路由：把请求交到函数，并支持动态段
- 模板：内置渲染
- 小工具：处理 cookie、请求头等
- 插件：可以挂到全局，也可以只挂几条路由

## Gee 框架

教程用 Go 写一个很小的框架，取名 Gee，来自站点名的前三个字母。作者最先接触的 Go 框架是 Gin。Gin 仓库大约 14K 行，其中测试约 9K，实现本身大约 5K，体量和 Flask 相近，小而完整。

七日教程的结构和不少实现都对照过 Gin，读的时候会看到相似的影子。

为了短，很多功能只做最小可用，但关键设计不偷工。路由即使只支持有限的动态规则，匹配也用 Trie，因为路由最在意查找速度。

## 推荐阅读

读这套笔记之前，最好已经能写简单的 Go 程序，会跑 `go test`，并且见过 Gin 的 `GET` 与 `Run`。语言速成、测试入门和 Gin 入门都是合适的预习材料。

标准库缺的三块，分别对应后面几天的主题，而不是第一天就全部塞进 `ServeHTTP`。

动态路径要解决两件事：把 `/hello/lin` 配到模式 `/hello/:name`，并把 `lin` 取出来交给处理函数。用一张 `map[完整路径]函数` 做不到，因为路径里有变量。Trie 把模式按 `/` 拆成节点，静态段和参数段分开存，查找时沿树往下走，失败就 404。分组则是给一簇路由加共同前缀，例如 `/admin`，鉴权可以挂在组上，而不是复制到每条路由。

模板那一天处理的是：业务代码不要自己 `Sprintf` 一段 HTML。框架提供加载目录、渲染名字的入口，底层仍是 `html/template`。最后一天处理 panic：某个请求里的空指针不应打垮整个进程，中间件在 `ServeHTTP` 外包一层 `recover`，把栈记下来并返回 500。

所以框架的核心不是再实现一套 TCP，而是把路由、上下文、分组、中间件、模板和恢复收成稳定的调用顺序。使用者只注册处理函数，其余步骤由引擎按固定次序执行。第一天先把这个入口从 `net/http` 的默认多路复用器换成自己的类型，后面每天往这个类型上加字段。
