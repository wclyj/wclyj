# Prometheus 与 Grafana

## 两条采集路线

观察一台机器，常见有两种组合。一种用 gopsutil 读取 CPU、内存和磁盘，把采样写入 InfluxDB，再交给 Grafana 画出来。另一种让 Prometheus 按周期把性能指标拉走，展示层同样用 Grafana。前者适合已经把指标推进时序库的系统，后者把“存什么、多久抓一次”交给 Prometheus 自己的抓取配置。

## Prometheus

Prometheus 专门做服务监控，模式是拉取：它按照任务列表去访问各个目标的指标接口，而不是等对方把数据推过来。

- Jobs 与 Exporters：一组抓取任务。Exporter 把 Redis、数据库这类系统的内部状态翻译成 Prometheus 能识别的文本格式。
- Service Discovery：按平台或注册中心自动找出实例，避免每加一台机器就手改配置。
- 短命任务：进程来不及被下一轮抓取就退出了，通常要改走推送网关，由任务在结束前把指标送上去。

### 取得并启动

从项目的发行页下载与本机系统匹配的压缩包，解压后直接运行其中的 `prometheus` 可执行文件。默认监听 `9090`。浏览器打开本机该端口下的 `/graph`，就进入自带的查询页。

### 在自带页面里看曲线

表达式框里可以填内置指标，例如表示抓取目标是否存活的 `up`。执行后切到图表面板，能看到一段时间内的折线。这个页面适合临时核对数据，配色和布局不适合长期值守，所以下一节把展示交给 Grafana。

## Grafana

Grafana 用 Go 编写，负责把时序数据画成仪表盘。下载对应系统的发行包并解压，进入 `bin` 目录启动 `grafana-server`。第一次启动要初始化自带的数据库，等待时间会明显长一些。成功后访问本机 `3000` 端口。

初始管理员的账号和口令都是 `admin`，登录后按提示改掉口令。添加数据源时选择 Prometheus，填入上一节那个服务的地址并保存，用页面上的测试按钮确认能连通。

接着可以导入一份现成的仪表盘描述，或在首页新建看板，把刚导入的面板挂上去。同一份序列可以换成另一种图形，只调整面板类型，不必重新采集。

## 还要看别的服务时

Redis、MySQL、Memcached 等不会自己吐出 Prometheus 格式。需要单独运行对应的 exporter，让它们监听一个 HTTP 路径，再在 Prometheus 的抓取配置里加上这些目标。官方的下载页按组件列出了这些导出器，版本要和被监控的服务兼容。

## 注意

拉取进程停掉之后，历史曲线还在不在，取决于本地时序目录有没有落盘。展示层地址填错时面板是空的，不必先怀疑图的配置。间隔太密会压垮目标，太疏会漏掉尖峰，应按指标变化速度来定。导出器的版本也要和被观察的服务匹配，否则指标名对不上，导入的面板会一片空白。抓取失败时先看目标页面能否单独打开，再看任务配置里的路径和端口，最后才怀疑展示层。自带查询页只适合临时核对，长期值守应把数据源接到展示层，并给看板设刷新间隔。主机指标和服务指标分开放，换数据源时就不必把面板全部重做。刷新间隔别设得比抓取还密。
