# HTTP 状态码

## 状态码的作用

状态码是响应起始行里的三位数字，用来概括这一次处理落在哪一类。

调用方应先看状态码，再决定重试、跳转或提示，然后才解析正文。

| 区间 | 类别 | 含义 |
| ---- | ---- | ---- |
| 1xx | 信息 | 请求已收到，仍在继续处理 |
| 2xx | 成功 | 服务端已按语义处理完毕 |
| 3xx | 重定向 | 还要客户端再做一次动作才能拿到资源 |
| 4xx | 客户端错误 | 按当前请求，服务端无法完成 |
| 5xx | 服务端错误 | 请求看起来可接受，但服务端处理失败 |

## 2XX 成功

### 200 OK

请求已被接受并正常处理。GET 通常带资源表示，POST 可能返回新建结果。

### 204 No Content

处理成功，但响应故意不带正文，例如删除完成。客户端不要再解析 body。若请求用 `Range` 只要文件的一段，成功时应返回 206，并用 `Content-Range` 标明区间，那不是 204。

## 3XX 重定向

### 301 Moved Permanently

资源已永久迁到 `Location` 给出的新 URI，以后应改用新地址。

### 302 Found

资源临时位于另一个 URI。本次请按 `Location` 再请求，但旧地址仍然有效，不必永久改写。它和 301 的差别在于迁移是不是长期的。

### 303 See Other

服务端希望客户端改用 GET 到另一个 URI 取结果。表单提交成功后常用它把浏览器带离 POST。

### 304 Not Modified

客户端带了条件头，服务端确认表示未变化，于是不回正文，让客户端用本地缓存。它归在 3xx，但不会把用户带到新地址。

## 4XX 客户端错误

### 400 Bad Request

报文语法错误、参数类型不对，或服务端无法理解字段。应修正请求后再发，而不是原样重试。

### 401 Unauthorized

缺少凭证或凭证未通过。响应里的 `WWW-Authenticate` 说明需要哪种方式。它表示尚未认证，不是“已经登录但权限不够”。

### 403 Forbidden

服务端已经理解请求，也知道调用方是谁（或明确拒绝匿名），但拒绝授权访问该资源。继续用同一身份重试通常没有意义。

### 404 Not Found

服务器上没有与该 URI 对应的资源。

### 405 Method Not Allowed

URI 存在，但不接受当前方法。响应头 `Allow` 会列出允许的方法，例如只允许 GET 与 HEAD。

## 5XX 服务器错误

### 500 Internal Server Error

服务端处理时发生未预期故障。是否重试要看接口是否幂等。

### 503 Service Unavailable

服务暂时不能工作，常见于过载或维护。有 `Retry-After` 时可按其提示再试。
