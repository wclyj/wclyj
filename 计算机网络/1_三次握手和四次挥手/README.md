# 三次握手和四次挥手

## 三次握手

### 概念

TCP 要提供可靠的字节流，通信双方必须先确认对方可达，并商量后续要用的参数。这些参数包括初始序号、最大段长度，以及接收窗口一类的流量控制信息。这个建立过程就是握手。

一条 TCP 连接的生命可以分成三段：

- 建立连接
- 传数据
- 释放连接

建立阶段要同时解决三件事：

- 每一方都能确认对方存在并且愿意通信
- 双方交换并认可本次连接的参数
- 两端为这条连接分配缓存、定时器等资源

### TCP 连接建立过程

握手交换的是 TCP 段，关键标志是 SYN、ACK，以及序号字段 seq、确认号 ack。

1. 客户端发出第一个段：SYN 置位，seq 取自己的初始序号 `x`。SYN 段本身不携带应用数据，但要消耗一个序号。客户端进入 `SYN_SENT`。
2. 服务器同意连接，回一个段：SYN 与 ACK 同时置位，seq 为自己的初始序号 `y`，ack 等于 `x + 1`。服务器进入 `SYN_RCVD`。
3. 客户端再回一个确认段：只有 ACK 置位，seq 为 `x + 1`，ack 为 `y + 1`。两端进入 `ESTABLISHED`。

序号的作用是给字节编号。接收方靠序号发现缺段、重复段和乱序段，这是可靠性的基础，不只是“给消息起个名字”。

第三步不再置 SYN。连接请求已经在前两步交换完毕，第三个段只是确认服务器的初始序号。

### 通俗的理解

- 客户端：“我准备好了，初始序号是 x。”
- 服务器：“收到 x，我的初始序号是 y，下一段请从 x+1 开始。”
- 客户端：“收到 y，下一段请从 y+1 开始。”

两边都听到了对方的序号，也把自己的序号送达对方，连接才算建好。

### 为什么是三次握手

四次也能把序号交换完，但第二步已经可以把“确认客户端的 SYN”和“发出自己的 SYN”放进同一个段，再拆开就是浪费一次往返。

两次则不够。第一次握手只证明客户端能发包、服务器能收包。服务器回包之后，如果没有第三次确认，服务器无法知道自己的 SYN 和初始序号有没有到达客户端，也就不能确认客户端具备接收能力。

超时重传会把这个问题放大。客户端发出的第一个 SYN 若在网络里滞留，客户端会以为失败而重发一个新的 SYN。后到的那个请求先被服务器接受并进入已连接状态后，早先滞留的旧 SYN 又到达，服务器若仅凭两次握手就再次打开一条连接，客户端却不会理睬这条过期请求。服务器侧就会留下一条没有对端的半开连接，白白占用资源。第三次握手让客户端明确确认“我认的是这一次”，过期 SYN 不会再单独把连接建立起来。

## 四次挥手

释放连接时，双方合计要交换四个段，用来关掉这条全双工通道的两个方向。

TCP 允许一端先停止发送，另一端继续把剩余数据发完。因此每个方向都要单独关闭：发完数据的一方发送 FIN，对端确认；对端发完后再发送自己的 FIN，并由先关闭的一方确认。

### 四次挥手过程

设客户端主动关闭，当前序号为 `u`，服务器序号为 `v`。

- **第一次挥手**：客户端发送 FIN=1、seq=u，声明自己不再发送应用数据，进入 `FIN_WAIT_1`。
- **第二次挥手**：服务器回复 ACK=1、ack=u+1，并可带上自己的 seq=v，进入 `CLOSE_WAIT`。客户端收到后进入 `FIN_WAIT_2`。此时客户端到服务器的方向已关，服务器仍可继续发送。
- **第三次挥手**：服务器也发完数据后，发送 FIN=1、ACK=1、seq=w、ack=u+1，进入 `LAST_ACK`。
- **第四次挥手**：客户端回复 ACK=1、seq=u+1、ack=w+1，进入 `TIME_WAIT`。服务器收到该 ACK 后进入 `CLOSED`。

### 挥手中的状态

- `CLOSED`：没有连接。
- `ESTABLISHED`：双方都可收发。
- `FIN_WAIT_1`：主动方已发出 FIN，正在等对方的 ACK。
- `FIN_WAIT_2`：主动方已收到 ACK，还在等对方的 FIN。这是半关闭：本端发送方向已经结束，仍可接收对端数据。
- `CLOSE_WAIT`：被动方已确认对方的 FIN，正在等待本端应用调用关闭，以便发出自己的 FIN。
- `LAST_ACK`：被动方已发出 FIN，正在等最后一个 ACK。
- `TIME_WAIT`：主动方已发出最后的 ACK，要在此停留一段时间。

### 为什么 TIME_WAIT 状态还需要等待 2MSL 后才能返回 CLOSE

四个段都发出去之后，按理想网络可以直接回到 `CLOSED`。实际网络会丢包。若最后那个 ACK 丢失，处于 `LAST_ACK` 的一方会重传 FIN。主动方若已经消失，就无法再确认，被动方会一直重试。

`TIME_WAIT` 保留足够长的时间，以便在收到重传 FIN 时把 ACK 再发一次。等待长度是 2MSL（两倍最大段生存时间）：一个 MSL 让在途的 FIN 有机会到达，另一个 MSL 让重发的 ACK 有机会被对方收到。这段时间也能让旧连接的迟到段从网络中消失，避免被同一四元组上的新连接误收。
