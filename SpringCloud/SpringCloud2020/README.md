# Spring Cloud 2020 学习索引

这一组笔记沿着一条调用链往下看：服务如何登记、如何被找到、调用失败时如何退让、配置如何下发、一次请求如何被串起来。

## 阅读顺序

1. 先建立整体图像：各组件各自解决哪一类问题，不急着堆依赖。
2. 用 Eureka 把两个进程注册到一起，再扩成双节点，体会单点挂掉之后的影响。
3. 了解 Netflix 组件进入维护期之后，注册、配置、限流可以换到哪些实现。
4. 在调用方进程里做负载均衡，对比网关或 Nginx 那种集中转发。
5. 用声明式 HTTP 客户端把地址和路径从业务代码里拿出去。
6. 给调用加上超时、降级和熔断，避免一个慢接口拖住整条链路。
7. 在边缘放一个网关，统一鉴权、路由和跨域。
8. 把配置从仓库或配置中心拉下来，而不是打进每个包。
9. 用消息总线把「配置变了」广播到全部实例，或只点名某几个实例。
10. 用消息通道把生产者和消费者隔开。
11. 给日志加上追踪号，再接到链路系统里看耗时。
12. 换到 Nacos，同时承担登记与配置，并区分命名空间、分组和数据编号。
13. 用 Sentinel 做限流和熔断，并把规则存到 Nacos，避免重启丢失。
14. 跨多个写库的业务，用分布式事务方案保证要么一起成功、要么一起回滚。

## 动手时的最小闭环

本地至少准备一个注册中心、一个提供者和一个调用方。每加一个新组件，只改一条链路，确认面板上能看到实例或规则，再进入下一篇。端口、服务名在各篇笔记里彼此错开，避免和别的示例抢端口。
