# Redis中的数据结构

## 前言

Redis 把数据放在内存里，用单线程执行命令，读写延迟通常在毫秒以内，所以缓存、计数、排行榜、会话都会用到它。对外主要是五种键：字符串、哈希、列表、集合、有序集合。很多项目只用过 `GET` 和 `SET`，把对象序列化成一整段文本塞进去。五种键各自对应不同的内存布局，选对了能少占内存，也能少发命令。

## 字符串

字符串是其余几种键的底座。值可以是短文本、一段 JSON、整数、浮点，也可以是图片或音频的二进制，Redis 不关心内容是不是可打印字符。

内部编码有三种，服务器按值和长度挑选：

- `int`：值是整数，并且落在 `long` 能表示的范围里
- `embstr`：一段较短的字节串，SDS 头和正文放在同一块连续内存里。3.2 之后，长度不超过 44 字节走这条路径
- `raw`：更长的字节串，头和正文分成两次分配

早期笔记常把分界写成 32 或 39 字节，那是旧版 SDS 头的算法。面试时说出「短串一次分配、长串分开分配」即可，具体阈值随版本变。

常见用法：

- 热点页面、配置项的缓存
- `INCR` 做计数器、限流窗口、发号
- 多台应用共享同一份会话
- 小块二进制，例如验证码图片

把所有对象都序列化进字符串也能跑，但改一个字段就要整段读出再写回，并发下容易互相覆盖。字段多、又常单独更新时，应改用哈希。

命令可以按场景记，不必先背内部编码：

```bash
SET page:home "<html>" EX 60
INCR api:login:count
INCRBY user:1001:score 5
GET page:home
```

`EX` 给秒级过期，适合验证码和短期页面。计数器不要用 `GET` 加 `SET` 自己加一，两条命令之间会丢增量，用 `INCR` 才是原子的。二进制用 `SET` 同样能存，客户端按字节读写即可，不要把图片编成十六进制再塞进去，那样体积会翻倍。

## 哈希

哈希保存一组字段和值，适合一个对象的多个属性，例如会员的昵称、城市、积分。

小哈希用压缩列表（7.0 起改为 listpack），大了就换成哈希表。经典的切换条件是两条同时成立才留在压缩结构里：

- 每个字段名和字段值都不超过 64 字节
- 字段个数不超过 512

任一条件被打破，就转换成哈希表。哈希表查找期望是常数时间，但每个键都有额外指针和装载因子留下的空槽，内存比紧凑编码大。

用哈希存会员资料，比把整份 JSON 放进字符串更直观，也可以只 `HGET` 一个字段。代价是要盯着编码转换：一旦膨胀成哈希表，内存会明显上涨。购物车也适合这个结构，字段是商品编号，值是件数；`HINCRBY` 就能加减。计数器若维度很多（每个接口一个计数），同样可以收进一个哈希，减少顶层键的数量。

```bash
HSET member:1001 nick ada city hz score 20
HGET member:1001 city
HINCRBY cart:1001 sku-18 1
HGETALL cart:1001
```

`HGETALL` 在字段上千时会堵住主线程，大哈希应改成分批 `HSCAN`。一个键里的字段没有单独的过期时间，过期是按整个键计算的。若每个字段寿命不同，就不要塞进同一个哈希。

## 列表

列表是有序序列，按下标访问两端是 O(1)，按下标访问中间则要沿链表走。它允许重复元素。要求成员唯一时应使用集合，不要寄希望于列表帮你去重。

3.2 之前有两种编码。同时满足下面两条时用压缩列表：

- 元素个数小于 `list-max-ziplist-entries`，默认 512
- 每个元素都小于 `list-max-ziplist-value`，默认 64 字节

否则退回普通双向链表。3.2 起用 quicklist 把两者接在一起：外层是链表，每个节点内部仍是一小段压缩列表，这样既能从两端 O(1) 进出，又不会让一整块连续内存无限变长。7.0 之后，quicklist 内部的压缩列表换成了 listpack。

因为保序，列表适合时间线、消息流、待办队列。`LPUSH` 配合 `RPOP` 得到先进先出；`LPUSH` 配合 `LPOP` 得到后进先出。阻塞版本 `BLPOP` 可以让消费者在空队列上等待。它没有确认和重试，只能当进程内或低可靠的临时队列，不能替代专门的消息中间件。

```bash
LPUSH feed:1001 "post-9" "post-8"
LRANGE feed:1001 0 19
RPOP job:mail
BLPOP job:mail 5
```

`LRANGE` 的下标从 0 开始，右端用 -1 表示最后一个元素。时间线只保留最近几十条时，`LPUSH` 之后立刻 `LTRIM key 0 49`，避免列表无限变长。`BLPOP` 的超时单位是秒，返回的是键名和元素两段，超时则返回空。

## 集合

集合无序，成员不可重复。插入顺序不会被保留。

编码二选一：元素全是整数，且个数小于 `set-max-intset-entries`（默认 512）时用整数集合；否则用哈希表，值的位置空着，只靠键表示成员存在。

无序、互异、能做并集 `SUNION`、交集 `SINTER`、差集 `SDIFF`，正好用来做标签。一篇文章的标签、一个用户点过的兴趣，都可以是一个集合。交集就是共同标签。

`SPOP` 弹出随机成员，适合抽奖后把名额拿走；`SRANDMEMBER` 只抽样不删除，适合展示「随机推荐」而不改变原集合。

```bash
SADD post:88:tags redis mysql index
SISMEMBER post:88:tags redis
SINTER user:1:tags user:2:tags
SRANDMEMBER post:88:tags 2
```

交集的代价和较小的那个集合有关，两个大集合做 `SINTER` 仍可能很慢，在线接口里要限制集合规模。判断存在用 `SISMEMBER`，不要把整个集合 `SMEMBERS` 拉回客户端再查找。

## 有序集合

有序集合在成员之外多了一个分数 `score`。成员仍然不能重复，分数可以相同。排序先看分数，分数一样再按成员的字典序。

元素少且成员短时用压缩列表（新版本是 listpack），两条都要满足：

- 成员个数小于 128
- 每个成员的字节长度都小于 64

否则改用跳跃表，并配上一张哈希表：跳跃表负责按分数范围扫描，哈希表负责用成员直接查分数，做到 O(1)。

排行榜是典型场景。直播间把当场点赞数当作分数、主播编号当作成员，`ZINCRBY` 累加，`ZREVRANGE` 取前十。课程站点的播放量、仓库的出库量，同一套命令就能做。

```bash
ZINCRBY room:live 1 anchor:7
ZREVRANGE room:live 0 9 WITHSCORES
ZRANGEBYSCORE room:live 100 200
```

`WITHSCORES` 会让返回值变成成员和分数交替出现。相同分数的名次是成员字典序，不是先到先得。要按时间打破平局，可以把时间戳编进分数的小数部分，或者把成员写成「分数相同则靠后缀区分」的字符串。分页不要用很大的 `ZREVRANGE` 偏移，排名靠后时用 `ZRANGEBYSCORE` 或记录上一页的分数做游标。

### 小结

五种键是对外的类型，不是唯一的内存结构。同一种键会在「省内存的紧凑布局」和「操作更快的通用布局」之间切换，阈值由值和长度决定。写业务时先问三件事：要不要保序、要不要唯一、要不要按数值排序。答案分别指向列表、集合和有序集合；对象的多个字段用哈希，单个值或计数用字符串。
