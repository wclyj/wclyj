# Redis缓存穿透-布隆过滤器

请求先过缓存，再谈怎样挡伪造键。

## 缓存穿透

商品详情先查 Redis，键是 `item:{id}`。命中就直接返回；未命中再查数据库，把行写回 Redis，然后响应页面。正常流量里，未命中只是偶发，数据库扛得住。

攻击者可以伪造大量从未出现过的商品编号。这些键在 Redis 里都不存在，请求会全部落到数据库，数据库也查不到行，于是既没有缓存被填上，下一次同样的伪造键还会再打一次库。流量够大时，数据库连接被打满，正常读写一起失败。这个现象叫缓存穿透：缓存层没有拦住，请求穿过它打到了库。

## 简单的解决方法

库里确认没有这一行时，仍然往 Redis 写一个占位，值用空串或一个约定的哨兵，并给一个较短的过期时间。同一个伪造键再次到来，命中的是这个占位，不再访问数据库。

占位不能没有过期时间，否则后来真正上架的商品会被空值挡住。过期时间也不宜和正常详情一样长，免得攻击者用海量随机键把内存撑满。这只是把「穿透」变成了「短命的空值」，键的空间仍然无限。要在进 Redis 之前就断定「这个编号根本不可能存在」，需要一个占内存很小的预检结构。

## 布隆过滤器

先看它能断定什么。

### 什么是布隆过滤器？

它用来回答「这个元素是否可能在集合里」。答案只有两种：一定不在，或者可能在。它不会出现「说不在、其实在」的漏判，但会出现「说可能在、其实不在」的误判。

适合的场合：

- 爬虫记住已经抓过的地址，跳过重复 URL
- 在很大的垃圾地址名单里判断某个邮箱要不要拒收，短信黑名单同理
- 把数据库里存在的主键提前放进去。请求到来时若判定「一定没有」，就直接返回，不再查缓存和数据库

### 原理

内部是一段初始全 0 的位图。误判率要求越低，位图越长，哈希次数通常也越多。位数和哈希个数可以由公式从「预计元素个数」和「目标误判率」算出来，不必手调。

用一个小例子把步骤走完。位图 12 位，三枚哈希 `h1`、`h2`、`h3`。放入 `sku-18`，三枚哈希落到 1、6、9，这三位改成 1。再放入 `sku-44`，落到 3、6、11，对应位改成 1。此时为 1 的下标是 1、3、6、9、11。

查询时同样算三枚哈希：

- `sku-90` 落到 1、4、9。第 4 位仍是 0，可以断定它没被放入过
- 某个从未放入的 `sku-77` 若刚好落到 1、6、11，三位全是 1，过滤器会说「可能在」。这就是误判：它被别人的哈希「撞」上了已经置位的格子

删除很危险。若把某元素对应的位改回 0，可能把别的元素共用的那一位清掉，造成漏判。标准布隆过滤器因此只支持放入和查询。需要删除时要换带计数的变体。

### 使用

Java 里常用 Guava 的 `BloomFilter`。依赖坐标是 `com.google.guava:guava`，版本按项目统一管理即可，不必锁死某一篇旧文章里的号。创建时传入预期插入量和目标误判率，误判率必须大于 0。

下面用一段独立的双哈希实现把参数和结果做实，避免只背 API。预计放入 20 万个整数，目标误判率 3%。按公式得到位图约 1,459,688 位（大约 178KB），哈希 5 次。把 `0` 到 `199999` 放进去，再用 `200000` 到 `399999` 这 20 万个肯定不在集合里的数去查，实测误判 6023 次，比率 0.0301，和 3% 的目标贴在一起。

```python
def locate(n, bits, rounds):
    digest = hashlib.blake2s(str(n).encode(), digest_size=16).digest()
    left = int.from_bytes(digest[:8], "little")
    right = int.from_bytes(digest[8:], "little") or 1
    for step in range(rounds):
        yield (left + step * right) % bits
```

放入时把 `locate` 给出的位设为 1；查询时这些位全是 1 才回答「可能存在」。业务侧应把「可能存在」当成放行：再查 Redis 和数据库。回答「不存在」才直接拒绝。

### 代码分析

两个输入是预计容量和可接受的误判率。容量估小了，真实误判会高于目标；估太大则位图空转。预检用 1% 到 3% 通常够，被误放行的请求仍会走原来的查库路径。

上面那次运行把放入段和探测段错开。误判次数除以探测段长度，应落在目标附近，换一批数会有抖动，不会每次都等于同一个分子。

上架主键要先放进过滤器再对外查询。新商品入库后必须补进去，否则会被当成「一定没有」。过滤器若只活在进程内存里，新扩出的进程是空的，要从库里把主键重新灌入，或把位图放到集中存储。空值缓存挡住的是重复的坏键，位图挡住的是坏键种类没有上界。两道可以一起用。
