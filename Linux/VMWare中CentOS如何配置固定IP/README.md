# 在 VMware 里给 CentOS 配固定 IP

## 前言

虚拟机若每次开机都向 DHCP 要地址，宿主机一重启，客户机地址就变。依赖固定地址的集群（例如各节点互相填写的控制面地址）会全部失联。下面把 CentOS 改成 NAT 模式下的静态地址，让重启之后仍是同一 IP。

## VMware 网络模式

新建虚拟机时，网卡一般有四种接法。装完 Workstation 后，宿主机的网络连接里会多出两块虚拟网卡。打开虚拟网络编辑器可以看到：VMnet1 对应仅主机，VMnet8 对应 NAT。桥接不单独占一块这样的虚拟网卡，它直接借用宿主机的物理网卡。

### 桥接模式（Bridged）

桥接可以看成从物理网卡上拉出一条桥，客户机和宿主机站在同一个二层网络里，向真实的路由器要地址。它的网络功能和一台独立电脑相同。

- 客户机与宿主机：能互相访问。两边各有一个同网段地址。
- 客户机与局域网其他机器：能互相访问，因为客户机地址在真实网段里。
- 客户机与客户机：只要都桥接到同一物理网络，就按普通主机互访。

这种模式下，客户机不经过 VMware 的地址转换，地址耗尽或网管禁止未知 MAC 时，它就拿不到地址。

### NAT 模式

NAT 是网络地址转换。宿主机充当带 DHCP 的路由器，客户机位于 VMnet8 后面的私网。客户机访问外网时，源地址会被换成宿主机的地址；外网不能主动连回客户机。

只要宿主机能上网，客户机通常不用再配交换机口就能上网。

- 客户机与宿主机：客户机可以访问宿主机在 VMnet8 上的地址。宿主机要访问客户机，需走 VMnet8 这个网段，而不是走宿主机的物理网卡地址。
- 客户机与其他主机：客户机可以向外发起连接，对方不能凭客户机的私网地址连进来。
- 客户机与客户机：同在 VMnet8 网段时可以互访。

数据包的路径是：客户机网卡接到 VMnet8，NAT 服务做地址转换后从物理网卡发出；回来的包再转换回客户机。DHCP 服务负责发地址。VMnet8 本身不直接“变成”客户机，它是这台虚拟交换机在宿主机上的接口。

### 主机模式（Host-only Adapter）

仅主机模式用 VMnet1 搭一张只有宿主机和客户机的网。默认没有 NAT，客户机不能上网。通过在宿主机上做路由或再接一张网卡，也可以扩展出别的连通方式，所以它比前两种更依赖手工规划。可以把它理解成一块专供虚拟机的内部网卡，所有选了仅主机的客户机都接在这张网上。

## 为什么使用 NAT 模式

桥接配置少，但会占用真实网段里的地址。地址紧、或网络不允许随意接入时，桥接就不合适。

既要客户机上网，又不想申请真实地址，就用 NAT。虚拟的 NAT 设备和 DHCP 服务接在 VMnet8 上，宿主机物理网卡只和 NAT 设备打交道，客户机从 DHCP 拿到私网参数后即可出网。

## 把客户机地址写成静态

### 核对宿主机上的虚拟网卡

客户机和宿主机在 NAT 下要靠 VMnet8 通信。在宿主机网络连接里打开 VMnet8 的 IPv4 属性。地址可以保持自动获得，让它跟随后面编辑器里还原出来的网段；若已经手写过，就改成与下面网关同一网段。

### 虚拟网络编辑器

菜单路径是“编辑 → 虚拟网络编辑器”。先点“还原默认设置”，把曾经改乱的网段清掉。还原后能看到桥接、NAT、仅主机三种。接下来只动 NAT：

1. 选中 NAT 模式对应的 VMnet8。
2. 勾选“将主机虚拟适配器连接到此网络”，并勾选“使用本地 DHCP 服务”。
3. 打开 NAT 设置，把网关写成 `10.8.20.2`，记下这个值。
4. 打开 DHCP 设置，查看起始和结束地址，例如 `10.8.20.128` 到 `10.8.20.254`。静态地址要落在这个范围里，又不要和已经租出去的地址冲突。
5. 回到主窗口点应用。

### 设置 CentOS 网络连接方式

关掉客户机电源，在虚拟机设置里打开网络适配器，选 NAT。这样客户机网卡会接到 VMnet8，而不是桥到物理网。

### 设置网络

启动 CentOS 后编辑网卡文件。接口名以 `ip link` 为准，下面按 `ens160` 举例：

```bash
nmcli device status
vi /etc/sysconfig/network-scripts/ifcfg-ens160
```

文件内容：

```text
TYPE=Ethernet
BOOTPROTO=static
NAME=ens160
DEVICE=ens160
ONBOOT=yes
IPADDR=10.8.20.140
PREFIX=24
GATEWAY=10.8.20.2
DNS1=119.29.29.29
IPV6INIT=no
```

这几项决定地址会不会在重启后留住：

```text
BOOTPROTO=static
ONBOOT=yes
IPADDR=10.8.20.140
PREFIX=24
GATEWAY=10.8.20.2
DNS1=119.29.29.29
```

`GATEWAY` 必须等于 NAT 设置里的网关。`IPADDR` 必须落在 DHCP 范围所示的网段内。`ONBOOT=yes` 漏掉时，重启后接口是关闭的，看起来像地址丢失。

CentOS 7 用：

```bash
systemctl restart network
```

CentOS 8 及更新版本网络脚本已经弱化，改用：

```bash
nmcli connection up ens160
```

### 测试

```bash
ping -c 3 www.baidu.com
ip -4 addr show ens160
```

三次都能收到应答，并且地址仍是 `10.8.20.140`，说明静态配置和 NAT 都生效了。再从宿主机 `ping 10.8.20.140`，确认宿主机能走 VMnet8 访问客户机。

## 最后

配好后若重启宿主机，客户机又上不了网，先看 Windows 服务里的 `VMware NAT Service` 和 `VMware DHCP Service` 是否在运行。这两个服务被设成手动、或被安全软件停掉时，客户机的网关和地址租约会一起失效。把它们改成自动并启动，再打开客户机，出网会恢复。静态地址写在客户机里，不依赖 DHCP 服务发租约，但没有 NAT 服务仍然出不了网。
