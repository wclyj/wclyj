# 中间件面试笔记导读

这一组材料把中间件追问收成一条复习线：先讲清楚为什么要引入，再把原理摊开，最后落到故障时怎么收场。每篇都按「抛出问题、拆开原因、换一组数字举例」来写，方便你换成自己项目里的量级再复述。

## 主题地图

- 消息中间件：解耦、异步、削峰，以及丢失、重复投递、顺序打乱和堆积
- 搜索集群：倒排、词典树分词、读写路径、海量查询怎么提速
- 缓存为什么要上，以及用错之后常见的四类事故
- Redis 基础卷：结构、落盘、过期淘汰、主从复制和哨兵
- Redis 进阶卷：槽位寻址、雪崩与穿透、双写对齐、竞争和事务
- 服务拆分：注册发现、协议、负载、容错、扩展点
- 接口幂等、调用先后，以及两把常见的分布式锁
- 登录态在多台机器之间如何共享
- 单库事务的隔离级别和传播行为
- 跨服务事务的五种收场办法
- 高并发系统通常会拼上的六块能力
- 分库分表、不停机搬迁、扩容和全局主键
- 读写分离，以及从库追不上主库
- 熔断、降级、限流怎样拦住故障蔓延

建议先把「为什么用」讲顺，再补一张自己画的结构图，最后用改过数字的例子收尾。外部视频和公众号不在这份目录里，直接读同级文件夹即可。

## 怎么用这组笔记

每篇开头都是面试里会连着追问的问题，中间用剖析把因果说完，再给一组新的数量级，避免背诵时只会重复别人的例子。代码和配置都换了类名、超时和样例数据，读的时候对着跑一遍，比只看结论记得住。

复习顺序可以按依赖来：先缓存和消息，再服务拆分与分布式事务，然后分库分表和主从延迟，最后用高并发、高可用两篇把前面的手段串起来。某一篇里的图如果原来是截图，这里改成了结构图，讲的时候可以在纸上把箭头再画一遍。

自测时不要先看剖析。先用自己的话回答标题下的问题，卡壳再翻对应小节，并把例子里的数字换成你项目里的 QPS、表行数或超时。能换算，说明不是在背段落。
