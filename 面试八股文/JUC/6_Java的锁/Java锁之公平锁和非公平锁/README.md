# Java 锁：公平锁与非公平锁

## 概念

### 公平锁

多个线程抢同一把锁时，严格按照申请先后排队。谁先调用加锁，谁就排在队伍前面，轮到自己才进入临界区。可以把它想成医院叫号：先取号的人先就诊，后来的人不能插队。

### 非公平锁

获取锁的次序不必等于申请次序。刚到的线程可以先试一次抢占，成功就进入，失败再排队。高并发下，长期抢不到的线程会饥饿。

## 如何创建

`java.util.concurrent.locks.ReentrantLock` 的构造参数是一个布尔值，用来声明是否公平。不传参数时走非公平实现。

```java
/**
 * true：按排队顺序授予锁
 * false：允许插队式抢锁
 * 省略参数时等价于 false
 */
Lock ticketLock = new ReentrantLock(true);
```

## 两者区别

**公平锁**：线程准备进入临界区之前，先看 AQS 等待队列。队列为空，或者自己正好是队头，才尝试占用；否则把自己挂到队尾，之后按先进先出被唤醒。

**非公平锁**：线程一进来先做一次 CAS 抢占。抢到了就不用排队；抢不到再走和公平锁类似的入队路径。少一次排队和唤醒，吞吐通常更高，代价是等待时间更不稳定。

## 题外话

`ReentrantLock` 是否公平完全由构造时的布尔值决定，默认实现偏吞吐，所以是非公平的。`synchronized` 同样不保证排队顺序，也属于非公平锁：它不会按申请先后把锁发给线程。
