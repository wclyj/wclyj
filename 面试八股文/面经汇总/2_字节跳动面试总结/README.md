# 字节跳动面试题复盘

## 前言

提前批的数据类后台岗位，流程大致是基础一轮、深入一轮、负责人一轮，再加一次短的人事沟通。基础轮看面有多宽，深入轮会在数据库和缓存上追问，负责人轮夹杂检索、注册中心和一道缓存淘汰的手写。算法在每一轮都可能出现，事先只看概念会在写代码时停住。

## 第一面

大约一小时，按项目往外延伸，没有死抠某一个源码分支。

- 自我介绍控制在项目和擅长的组件上
- 为什么投后台，而不是和研究方向更贴近的岗位。要能说出自己写过的服务，而不是只说兴趣
- 开放授权协议在解决什么。资源所有者把有限权限授给第三方，第三方拿令牌访问，而不是拿用户的密码
- 做过的开源框架里，哪些被真正读过源码
- 文章发布经过哪些步骤，系统是单作者还是多作者
- 静态站点生成器和动态博客的差别：一个在构建时产出页面，一个在运行时查库，后者多了账号、评论和后台
- 为什么引入消息队列。削峰、解耦投递和写库，而不是为了“架构完整”
- 几种队列的差别：一个吞吐高、持久化方式不同，一个适合日志流，一个协议更重、运维更轻，要按消息量和顺序需求选
- 为什么把热点文章放进缓存，热点是怎样算出来的
- 只靠人工推荐位会让旧文章永远占着高位，热度不随时间下降。可以在分数里减去时间衰减，或给推荐位单独的过期时间
- 第三方登录组件会不会把令牌写进日志。要看它是否落盘密钥，回调地址是否可被篡改
- 缓存主线程会不会因为命令切换而失去原子性。单条命令在主线程里跑完，不会被另一条命令从中间切开
- 单线程怎样同时照看很多连接：复用器告诉它哪些描述符可读，它再逐个执行命令
- 一个 2MB 的值会怎样。大值阻塞主线程、复制变慢、过期删除也重。单个值的上限远大于此，但不该用来存这么大的对象
- 分片集群怎样划分槽位，主从复制是全量加增量命令
- 哨兵负责发现主节点失效并完成切换，它不是分片方案
- 怎样查看机器负载：看平均负载和处理器核数是否匹配
- 查看、跟踪、编辑文件的命令各做什么。跟踪适合看追加的日志，编辑器才改内容
- 打开很大的文件时不要一次读进编辑器，按窗口查看或分页
- 3 开头的状态码表示还要继续，常见是跳转
- 4 开头多半是请求有问题，5 开头多半是服务端自己失败

第一道笔试题是合并区间。给若干闭区间，重叠或端点相接的要并成一段。

```python
def merge_ranges(chunks):
    ordered = sorted(chunks, key=lambda pair: pair[0])
    merged = []
    for start, end in ordered:
        if not merged or start > merged[-1][1]:
            merged.append([start, end])
        else:
            merged[-1][1] = max(merged[-1][1], end)
    return merged

print(merge_ranges([[1, 3], [2, 6], [8, 10], [9, 12]]))
```

`[1,3]` 与 `[2,6]` 重叠，合成 `[1,6]`；`[8,10]` 与 `[9,12]` 合成 `[8,12]`。先按左端排序，否则无法一次扫描。

第二题是出现次数最高的前若干个值，题目保证次数互不相同。例如 `[4,4,9,9,9,7]` 取前 2 名，应得到 9 和 4。

先统计次数，再把“次数 → 值”倒过来。因为次数唯一，倒转不会撞键。次数最大不超过数组长度，从大到小试这些次数即可，整体仍是线性。

```python
def top_freq(nums, limit):
    freq = {}
    for n in nums:
        freq[n] = freq.get(n, 0) + 1
    by_count = {count: value for value, count in freq.items()}
    found = []
    for count in range(len(nums), 0, -1):
        if count in by_count:
            found.append(by_count[count])
            if len(found) == limit:
                break
    return found

print(top_freq([4, 4, 9, 9, 9, 7], 2))
```

若次数可能相同，倒转会丢值，那时应把值放进大小为 limit 的堆，而不是建这张反向表。

反问时可以确认算法和项目哪边更弱。这一轮能进下一轮，通常只说明广度过关。

## 第二面

大约五十分钟，开始追问原理。

- 项目是否开源，用的什么许可证，有没有真实用户
- 两套检索引擎的倒排索引：词到文档列表，列表里还可以带词频和位置
- 中文分词器怎样切词，词典和统计各自靠什么
- 自己更熟数据库还是缓存，要主动把话题接到准备过的那一边
- 聚簇索引为什么是 B+ 树：叶子放行，内结点只做路由，叶子互相连接
- B 树把记录放在内结点，扇出更小，范围扫描也不能顺着叶子走
- 索引形态的演进：全表扫描、哈希、会退化的二叉树、严格平衡的二叉树、多路的 B 树，最后才是 B+ 树。哈希做不了范围
- 事务是一组要么一起提交、要么一起撤销的操作，并满足原子、一致、隔离、持久
- 隔离级别从读到已提交、可重复读到串行，分别还可能看到脏读、不可重复读、幻读。默认级别靠锁和多版本把其中大部分挡住
- 可重复读保证同一行再读不变；幻读是同一范围里出现了新行。两者都和“读了两次”有关，对象不同
- `LIKE` 不是一定不用索引。左边是常数的前缀匹配可以用上普通索引，以通配符开头则不行
- 缓存里具体放了什么键，过期时间怎样定
- 分布式锁可以用带过期时间的占位键，释放时核对持有者，避免删掉别人的锁
- 先更新数据库再删缓存，失败的删除要重试。短暂不一致要能接受
- 查询不存在的键会穿透到数据库。可以缓存空值，或在前面放一个能判断“一定没有”的过滤器
- 大面积同时过期会把流量打回数据库。过期时间加随机抖动，或加互斥只放一个请求去回源
- 热点突然出现、缓存还没有时，用单飞把同一键的回源合并成一次
- 虚拟机里堆、虚拟机栈、本地方法栈、程序计数器、元空间各放什么
- 怎样判断对象可回收：从根出发达不到。算法有标记清除、复制、标记整理、分代
- 新生代用复制是因为垃圾比例高，活着的少，复制更便宜。老年代存活多，复制要准备同等大的空闲区，不划算，所以用整理
- `volatile` 保证可见和有序，不保证 `i++` 原子。写操作会插入内存屏障，让别的处理器看到新值
- 到处加它并不能替代锁，屏障也有成本，语义还容易被误当成原子
- 线程状态包括新建、运行、阻塞、等待、超时等待、结束。进程是资源分配单位，线程共享进程的地址空间
- 多线程而不是多进程，是为了共享数据和更轻的切换。隔离需求强时才拆进程
- 查端口和进程可以用套接字统计或进程过滤
- 链表每两个结点交换一次。`1→2→3→4→5` 得到 `2→1→4→3→5`

```python
class Node:
    def __init__(self, value, nxt=None):
        self.value = value
        self.nxt = nxt

def swap_pairs(head):
    dummy = Node(0, head)
    prev = dummy
    while prev.nxt and prev.nxt.nxt:
        first = prev.nxt
        second = first.nxt
        first.nxt = second.nxt
        second.nxt = first
        prev.nxt = second
        prev = first
    return dummy.nxt
```

画三个指针比背代码更稳：前驱、这一对的左结点、右结点。循环条件是后面还够一对。

收尾会问毕业时间和是否实习岗。这一轮的反馈常常是缓存尚可、数据库索引和隔离级别不熟。

## 第三面

大约五十分钟，负责人会从项目跳到检索、服务发现和操作系统。

- 为什么代码托管在国内平台而不是国际平台，英文阅读是否够用
- 开源项目里自己负责的模块，而不是星标数量
- 两套检索是否同时在用，用语句做搜索时怎样避免全表模糊匹配
- 底层都用同一套倒排库时，差别在分布式和运维模型：一边是分片和副本天然在一起，一边更像主从加外部集群
- 新词不一定能被词典切对。除了人工加词，还可以用基于统计的切分，让共现频率决定边界
- 字典树适合前缀提示：共享前缀，查找代价跟词长有关，而不是跟词表大小线性相关
- 多个服务打成多个包仍放在一台机器上，机器故障会一起不可用。要拆到不同机器，并让同一服务有多个副本
- 注册中心挂了，已有实例可以继续用本地缓存调用；新实例的注册会受影响。所以注册中心自己也要集群
- 选主看投票是否超过半数，同一轮只有一个候选当选。一致性协议保证多数派确认后的日志不会丢
- 给一张表：主键 `id`，以及 `name`、`status`、`created_at` 上各自的普通索引。条件是 `status = 1 AND name = 'lin'`

可能只用到其中一个索引，再回表过滤另一列；优化器若认为两个索引都便宜，也可能做索引合并，把两份主键做交集。不要断言“条件有几列就用几个索引”。

- 慢查询先看执行计划：访问类型、用了哪棵索引、扫描行数、有没有临时表和文件排序
- 缓存为什么扛得住高并发：内存、复用、单线程执行命令
- 一个线程照看很多连接，不是为每个连接做一个线程，所以不存在那些连接之间的线程切换
- 客户端连上之后，服务端仍能读别的连接，因为等待发生在复用器上，不发生在某一条连接的阻塞读上
- 每秒十万次命令，说明平均一次命令要在微秒级做完，不能在命令里做磁盘随机读
- 有序集合用跳表，数据库索引用 B+ 树。跳表方便按分值做范围，实现也比页式树轻；数据库要按页组织磁盘，B+ 树的叶子链表和扇出更合适
- 高速缓存、主存、虚存、外存：越靠上越快越小。虚存让进程看到连续地址，缺页时才从外存调入
- 置换算法有先进先出、最近最少使用、时钟算法。最近最少使用可以用哈希表加双向链表做成均摊常数时间：命中则挪到表头，满了就淘汰表尾
- 手写时先讲清这两个结构，再写查找、插入和删除。只写链表会把查找变成线性扫描

反问可以问语言在团队里的比例。编码反馈差，通常是因为淘汰算法没有在限定时间内写完边界，而不是思路完全偏了。

## HR面

大约十分钟，核对动机和稳定性。

- 为什么考研选择这所学校
- 入学以来最受挫的一件事，以及后来怎样补
- 还想改的短板要具体，例如算法题量和数据库执行计划
- 最有成就感的一件事，最好是能被验证的作品
- 能接受的城市，以及还在流程中的其它公司
- 找工作时更看重业务、团队还是技术栈
- 毕业时间，同学是否也在投同一批岗位

结果通常要等各轮汇总，不会在这十分钟里当场决定。人事题回答短，不要重复技术面已经讲过的架构。
