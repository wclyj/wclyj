# 京东零售提前批 Java 一面

## 前言

零售方向的数据中台岗位，一轮大约围绕实习项目往下拆，从缓存问到服务治理，再回到集合和回收器。回答时每次只展开自己用过的那一个组件。

## 第一面

- 自我介绍
- 从什么时候开始写 Java
- 挑一段最熟的实习，说明模块和自己的改动
- 项目用了哪些框架，为什么是这几个
- 为什么要放缓存。数据会变时，先改库再删键，而不是只改缓存
- 登录态放在哪里，操作日志靠什么字段把同一个人串起来
- 单体如果继续长，会在发布、故障隔离和数据所有权上遇到什么问题
- 微服务想拆的是独立部署和独立扩容，不是先把高并发拆没
- 调用链变长、排障变难、数据不能再做跨库事务
- 声明式客户端怎样把接口变成远程调用
- 客户端负载均衡有哪些策略：轮询、随机、按权重、按响应时间
- A 调 B、B 调 C，C 变慢时怎样避免线程被拖光。超时、舱壁和熔断要分开说
- 熔断器怎样统计失败，打开之后怎样降级并试探恢复
- 集合里列表、集合、队列、映射各解决什么
- 数组列表和老的同步列表：后者方法上带锁，扩容方式也不同
- 散列映射和旧的同步映射：后者全表锁，前者允许空键
- 并发映射为什么比整表锁快：锁的是桶头，读大多不加锁，长桶还会树化
- 链表改成树之后，查找从线性变成对数
- 怎样判断垃圾：引用可达性。算法有标记清除、复制、标记整理
- 低配机器用单线程回收，是为了少跟业务抢那一个核
- 资源充足时，低延迟选并发标记清除一类，大堆再考虑分区收集
- 池里的线程数：偏计算时靠近核数，偏等待时可以再放大，并用队列长度保护
