# 滴滴提前批 Java 三轮技术面

## 前言

三轮技术面可以排在同一个下午，每轮大约半小时到一小时。第一轮偏基础和项目协作，第二轮偏算法和请求链路，第三轮把项目、回收器和并发容器串起来。准备时每一题都要能落到自己写过的模块，否则追问一轮就会断。

## 第一面

大约三十分钟。

- 前端和后端都做过时，职业规划要说出以后主要写哪一层
- 初级、中级的差别在于能不能独立定位故障，而不是会的框架数量
- 读过的书要能讲出一章，例如并发容器或索引，不要只报书名
- 微服务不能直接提高单机吞吐。它解决的是独立发布和故障隔离。单服务从 200 QPS 到 400，先做无状态水平扩展和负载均衡
- 已经能靠多副本扛住流量时，再拆服务是为了团队边界和发布节奏，不是为了数字本身
- 日常问题多在调用超时、配置漂移和链路太长
- 定位慢在哪一跳，可以用链路号把日志串起来。原理是入口生成号，下游继续传递
- 注册中心的面板只能说明进程还在心跳，不能说明接口逻辑正确
- 从浏览器的网络面板看哪一个接口慢，再进对应服务的日志
- 另一套远程调用框架以接口为中心，注册和负载均衡是内置能力。要能对比它和当前用的那一套
- 优势落到具体经历：独立把某一个慢查询或一次泄漏查清
- 数组列表按下标访问是常数，链表插入便宜但查找要走链。数组列表扩容通常按 1.5 倍复制到新数组
- 树的遍历有前序、中序、后序和按层。递归或用栈都能做
- 索引按结构分聚簇、二级、全文；按算法分 B+ 树和哈希。主键和普通索引在默认引擎里都是 B+ 树
- 执行计划里看 `key` 和 `type`，确认有没有走期望的那棵索引
- 项目文档至少要有背景、接口、数据表、部署和已知限制
- 前后端并行靠事先约定的接口和返回样例，前端可以用假数据继续做页面

反馈往往是：广度可以以后补，但要先有一块能讲深的。

## 第二面

大约一小时，先写代码，再顺着一次请求往下问。

第一题：报酬按天数递增。第 1 天 1 元，接着 2 天每天 2 元，再接着 3 天每天 3 元。问第 n 天结束时一共多少钱。

第 3 天是 `1+2+2=5`，第 10 天是 `1+2+2+3+3+3+4+4+4+4=30`。一层循环每次找出“这一天落在哪一档”即可。也可以解不等式，找到最大的档位 k，使 `k(k+1)/2` 不超过 n，再把完整档的和加上剩余几天。

```java
static int pay(int day) {
    int total = 0;
    int rate = 1;
    int left = day;
    while (left > 0) {
        int span = Math.min(rate, left);
        total += span * rate;
        left -= span;
        rate++;
    }
    return total;
}
```

接着把一次接口调用讲完整：域名解析、建立连接、网关或过滤器、分发到控制器、参数绑定、业务、持久层，再把结果写回。过滤器若缺失，认证和编码会散落到每个控制器。

映射器负责把地址找到方法。没有它，就要自己维护一张表。容器里还能说出单例、工厂、代理和模板方法分别出现在哪。

接口代理要求有接口，在方法前后加逻辑；子类代理不要求接口，但不能覆盖 final 方法。事务和部分切面就是这样织进去的。

第二题是排复习时间。共 d 天，总时长固定，每天有下限和上限。若有解，输出一组每天的时长，并且希望前面的天尽量长；无解就明确拒绝。

做法：先检查总和是否落在“每天都取下限”和“每天都取上限”之间。然后每天先放上限，若总和超出，就从最后一天往前减，直到等于目标。这样前面的天保持更长。边界是某天减到下限仍超出，则无解。面试里先讲这个贪心，再写代码。

状态码按首位分：1 继续、2 成功、3 跳转、4 客户端问题、5 服务端问题。要造出 4，可以请求不存在的路径或故意不带必填参数；要造出 5，可以在处理里抛出未捕获异常。

消息队列用来削峰和解耦。选型看吞吐量、延迟、是否要严格顺序和事务消息，而不是看哪一个名字更熟。底层往往是磁盘日志加消费位点。阻塞队列则是进程内的等待结构：满了生产者等，空了消费者等。

这一轮的建议通常是把写题的速度练稳，项目故事已经够用。

## 第三面

大约一小时，围绕项目和运行时。

- 为什么做这个项目，核心功能有哪些，哪些是自己写的
- 前端框架为什么选它：上手成本和组件生态，另外两套更偏不同的状态管理方式
- 网关或反向代理怎样把静态文件和接口分开。静态资源可以直接由代理服务器提供，单独映射是为了缓存策略和权限路径不同
- 权限模型用用户、角色、权限三张关系。另一类模型按资源和动作配置，不手写角色也可以
- 安全框架把认证和授权拆开，过滤器链决定谁先执行
- 服务不要把内部端口直接暴露到公网。网关统一入口，再做鉴权和限流
- 服务之间从手写地址调用，演进到声明式客户端，地址改由注册中心给出
- 反向代理把外部路径转到内部实例。注册中心则是实例自己来登记
- 两种注册组件的差别在于一致性和健康检查的模型，以及是否同时带配置推送
- 方法区线程共享，里面是类的结构信息。堆也共享，对象本身不靠复制到线程私有区来避免冲突，可变状态要用锁或线程封闭
- 线程封闭的一种做法是把变量放进线程自己的映射。用完要删，否则线程池会把值留到下一个任务
- 幂等指同一请求执行多次和执行一次效果相同。重复提交可以用请求号做唯一键，或在短时间里拒绝相同的调用方加接口
- 堆分成年轻代和老年代。年轻代再把一块大的分配区和两块存活区按大约 8:1:1 划分，是因为多数对象很快死亡，复制收集只需要搬剩下的那一小部分
- 大对象、长期存活、以及存活区放不下时，会进入老年代。老年代空间不够、或者担保失败，会触发整堆回收
- 年轻代回收频率高、停顿短。整堆回收慢。并发收集器把大部分标记和业务线程重叠，只在少数阶段停顿
- 低延迟、堆不特别大时用并发标记清除；堆很大、希望停顿时间有上限时用分区收集。前者有碎片，后者要维护记忆集
- 散列映射在扩容和树化时都不是线程安全的。7 的头插在并发搬迁时可能成环，8 改成尾插，并在长度足够且链超过阈值时树化
- 并发映射放弃固定段锁，是因为段数不能随扩容增长。空桶比较并交换，非空桶只锁头，粒度更细
- 红黑树的高度是对数，所以查找是对数。它比严格平衡的树旋转更少，插入更合适
- 非递归前序遍历：根入栈，弹出时访问，再先压右孩子、后压左孩子

```java
void preorder(TreeNode root) {
    java.util.ArrayDeque<TreeNode> stack = new java.util.ArrayDeque<>();
    if (root != null) {
        stack.push(root);
    }
    while (!stack.isEmpty()) {
        TreeNode cur = stack.pop();
        System.out.println(cur.val);
        if (cur.right != null) {
            stack.push(cur.right);
        }
        if (cur.left != null) {
            stack.push(cur.left);
        }
    }
}
```

网络分层从链路、网络、传输到应用，能说出每层的职责即可。三次握手是同步、同步加确认、再确认，两次分不清对方是否收到了自己的确认。四次挥手是因为对方可能还有数据要发，关闭方向要各自确认。

坚持做项目的理由要具体到某一条自己还在维护的能力，例如某次把查询从全表扫改成覆盖索引。

## 后言

技术面全部结束之后才轮到人事，结果不一定当天出来。复盘时把三轮里没答上的题单独抄出来，每题补一段能讲三分钟的说明，比再看一遍项目介绍有用。
