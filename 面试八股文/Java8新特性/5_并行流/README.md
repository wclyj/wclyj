# 并行流与顺序流

## 并行流

并行流把一份数据切成多段，每段交给不同的工作线程计算，最后再把各段结果合并。

Java 8 的流可以在同一条链上切换策略：`parallel()` 改为分段并行，`sequential()` 改回按源顺序逐个处理。切换的是执行方式，过滤和映射怎么写不用另做一套。数据量小、每步又很轻时，拆分和合并的开销可能盖过收益。

## Fork/Join框架

### 概念

框架把一个大任务拆开：能再分就 fork 成子任务，小到阈值就直接算，再把子结果 join 起来。并行流的数字范围和数组拆分，底层就是这样调度的。

拆分有下限。任务已经比调度本身还便宜时，继续拆只会更慢。

### 采用 工作窃取 模式

每个工作线程带着自己的双端队列。自己拆出的子任务放在队尾，自己也从队尾取。别的线程无事可做时，从别人的队头偷一个任务，不必干等。

普通池里，线程一旦卡在某个子任务上就只能闲着。窃取让它转去执行还没人领的子问题，等待更短。代价是偷任务要做同步，而且子任务不能随便改同一份可变状态，否则合并结果会错。
