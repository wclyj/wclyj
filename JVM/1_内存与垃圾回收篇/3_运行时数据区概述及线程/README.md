# 运行时数据区概述及线程

## 概念

类完成装载、验证、准备、解析和初始化之后，执行引擎才按字节码推进。引擎读写的场所就是运行时数据区。可以把它看成车间：工作台是数据区，工人是执行引擎。工人换班，个人台面上的在制品跟着换，公共货架则留着。

内存位于磁盘或网络与处理器之间。外部数据先进入内存，处理器再从内存取指、取数。规范统一了各区域的职责，各家实现在边界和收集策略上仍有差别。下面按 HotSpot 的经典布局来看。

## 分类

一部分区域随虚拟机启动创建、随进程退出销毁，由所有线程共享，主要包括堆、方法区（JDK 8 起为元空间）和代码缓存。另一部分与线程一一对应，线程开始时建立、结束时销毁。每条线程独立拥有程序计数器、Java 虚拟机栈和本地方法栈。

私有的是计数器和两块栈，共享的是堆以及堆外的类元数据、代码缓存。直接内存也不属于某一条线程的栈，回收时机和 Java 堆并不同步。堆对象任何线程都可能碰到；局部变量表则只有本线程的字节码能访问。

各区域的分工可以先记成这样：

- 程序计数器保存当前线程下一条字节码的地址。规范明确这块区域不会发生内存溢出，也不做垃圾回收。
- Java 虚拟机栈保存 Java 方法的栈帧。
- 本地方法栈保存 native 调用。HotSpot 把两块栈合成一块，由 `-Xss` 统一限制。
- 堆存放实例和数组，是垃圾收集的主要场所。
- 方法区存放类型信息和运行时常量池。JDK 7 把字符串池移入堆，JDK 8 用本地内存中的元空间取代永久代。
- 代码缓存存放即时编译得到的机器码，空间不足会单独报错。

## 线程

线程是进程内的一条执行流。JVM 允许应用同时运行多条线程。HotSpot 把 Java 线程一对一映射到操作系统线程：Java 线程准备执行时创建本地线程，Java 线程终止后本地线程被回收。

操作系统把本地线程调度到可用处理器上。本地线程初始化完成后进入 Java 侧的 `run`。切换由操作系统完成，虚拟机自己不做时间片轮转。

## 虚拟机自带的系统线程

用调试器或控制台观察一个刚启动的进程，除了执行 `main` 的线程以及业务代码创建的线程，后台还有一批系统线程。HotSpot 里主要是下面几类。

- 虚拟机线程。它的操作要等虚拟机到达安全点才进行，这样堆在操作期间不会被业务线程改写。工作包括停顿式垃圾收集、导出线程栈、挂起线程，以及撤销偏向锁。
- 周期任务线程。它处理定时事件，例如定时器到期，用来驱动周期性调度。
- 垃圾收集线程。为不同种类的收集行为提供执行力量。有的只在停顿时出现，有的与业务线程并发。
- 编译线程。在运行期把字节码编译成本地代码。
- 信号调度线程。接收操作系统信号，再调用虚拟机内部相应的处理例程。

这些线程不是 `main` 创建的。

## 参数与观察

容量不由单一开关决定：栈看 `-Xss`，堆看 `-Xms` 与 `-Xmx`，元空间看 `-XX:MetaspaceSize` 与 `-XX:MaxMetaspaceSize`。观察线程可以用 `jcmd 4281 Thread.print`。

## 易错点

“Java 内存”不等于堆。计数器、栈、元空间、代码缓存和直接内存都在 `-Xmx` 之外。私有区域本身不做垃圾回收，但栈上引用着的堆对象仍是根。日志里的停顿常常是虚拟机线程在安全点组织了收集。JDK 8 的方法区实现是元空间，字符串池却在堆中，不能再都当成永久代里的数据。
