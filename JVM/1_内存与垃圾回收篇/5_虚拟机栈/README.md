# 虚拟机栈

## 概念

Java 的字节码按栈式指令集设计。处理器的寄存器数量和约定各不相同，字节码若直接写成寄存器指令，就无法在另一套 CPU 上原样执行。栈式指令种类少，编译器好写，代价是完成同样的运算要更多条压栈和弹栈，解释执行时的分派次数更高。

很多人把 JVM 的内存只分成堆和栈。这个分法太粗，但确实抓住了两块最常被提到的区域：栈是运行单位，堆是存放单位。栈回答方法怎样被调用、局部数据怎样传递；堆回答对象放在哪里。程序计数器、方法区、直接内存都不在这两块里。

Java 虚拟机栈在早期资料里也叫 Java 栈。每条线程在创建时得到自己的一份，里面是一帧一帧的栈帧，一次 Java 方法调用对应一帧。它是线程私有的。

### 生命周期

栈的寿命和线程相同。线程结束，这份栈被释放，不需要收集器来“回收栈”。

### 作用

它主管 Java 方法的执行：保存局部变量和部分中间结果，并参与调用与返回。局部变量相对的是成员变量。局部变量既可以是基本类型，也可以是指向堆对象的引用。引用本身在栈帧里，对象还在堆上。

### 特点

栈的分配和释放就是移动栈顶指针，速度只比程序计数器慢一档。虚拟机对 Java 栈只有两类动作：方法开始时压入一帧，方法结束时弹出一帧。帧弹掉之后，里面的局部变量表一并失效，不存在“栈上的垃圾对象等着收集器来扫”。可能发生的是溢出，而不是堆那种可达性分析。

### 两种错误

规范允许每一条线程的栈容量在创建时选定为固定值，也允许实现按需扩张。

- 固定容量时，线程需要的栈深超过了这份栈的上限，虚拟机抛出 `StackOverflowError`。
- 允许扩张时，扩张申请不到内存，或者新建线程时连栈都分配不出来，抛出 `OutOfMemoryError`。

无界递归是第一种错误的典型来源。

```java
public class DepthProbe {
    static int depth;

    static void dive() {
        depth++;
        dive();
    }

    public static void main(String[] args) {
        try {
            dive();
        } catch (StackOverflowError ex) {
            System.out.println(depth);
        }
    }
}
```

打印出来的深度不是一个固定常数。帧越大、`-Xss` 越小，数字越小。不要把某一次运行得到的深度写进代码当阈值。

### 栈容量参数

`-Xss` 设置的是每条线程的栈上限，它直接限制调用链能有多深。例如 `-Xss512k` 和 `-Xss1536k`。这个值过小，虚拟机可能在启动时就拒绝，因为平台有自己的下限；过大，则每多一条线程就多占一块本地内存。它不是堆参数，调 `-Xmx` 不会让递归变得更安全。

## 栈里存放的单位

每条线程有自己的栈，栈里的数据以栈帧存在。该线程上正在执行的每个 Java 方法各有一帧。帧是一块内存，记录这次调用需要的局部变量、操作数、返回位置和常量池引用。

虚拟机对栈的操作就是压帧和弹帧，遵循后进先出。在一条线程的某个时刻，只有栈顶那一帧是活动的，称为当前帧。当前帧对应的方法是当前方法，定义该方法的类是当前类。执行引擎的字节码只对当前帧做读写。

当前方法调用另一个方法时，新帧被压到栈顶，成为新的当前帧。被调用者返回后，新帧弹出，上一帧恢复为当前帧，返回值按约定进入调用者的操作数栈。

```java
public class FrameOrder {
    public static void main(String[] args) {
        enter();
    }

    static int enter() {
        System.out.println("enter-begin");
        int value = middle();
        System.out.println("enter-end");
        return value;
    }

    static int middle() {
        System.out.println("middle-begin");
        int value = leaf();
        System.out.println("middle-end");
        return value;
    }

    static int leaf() {
        System.out.println("leaf-begin");
        int value = 45;
        System.out.println("leaf-end");
        return value;
    }
}
```

输出顺序是 `enter-begin`、`middle-begin`、`leaf-begin`、`leaf-end`、`middle-end`、`enter-end`。调试器里的调用栈从上到下正好与压栈顺序相反：叶子方法在顶上。不同线程的帧不能互相引用，一条线程无法把另一条线程的局部变量表当成自己的操作数。

方法返回有两种方式。一种是执行到某条 `return` 指令，属于正常完成。另一种是抛出异常且本方法没有处理，帧同样被弹出。两种出口都会让当前帧失效。

### 帧内有什么

每一帧里包含：

- 局部变量表。
- 操作数栈，也叫表达式栈。
- 动态链接，即指向运行时常量池里该方法的引用。
- 返回地址，用来在正常退出时回到调用点的下一条指令。
- 实现可选的附加信息，例如调试数据。

一帧占多少空间，主要看局部变量表和操作数栈有多深。这两项的上限在编译期写进方法的 `Code` 属性，运行期间不会把某一帧再撑大。调用链能嵌套多深，则由整段栈的容量决定。单个方法的参数和局部变量越多，一帧越大，同样的 `-Xss` 下能嵌套的层数越少。

## 局部变量表

局部变量表是一个数字数组，存放方法参数和方法体内的局部变量。元素类型包括基本类型、引用，以及 `returnAddress`（和异常表配合的历史类型）。它建在线程私有的栈上，不存在“别的线程改我的槽位”这种数据竞争。容量由编译期确定，记在 `max_locals` 里，方法执行过程中槽位总数不变。

表只在本次调用期间有效。调用开始时，虚拟机把参数装入槽位；调用结束，整张表随帧销毁。被表中引用直接或间接指着的堆对象，是垃圾回收的根，在帧还活着时不会被收掉。

### 槽位

参数从下标 0 开始往后放。32 位以内的类型占一个槽，包括 `int`、`float`、引用和 `returnAddress`。`long` 和 `double` 占两个连续槽，访问时使用第一个下标。`byte`、`short`、`char` 在进入局部变量表或操作数栈之前会提升为 `int`。`boolean` 也按 `int` 存储，0 表示假，非 0 表示真。

实例方法和构造器会把 `this` 放在 0 号槽，其余参数按声明顺序后移。静态方法没有 `this`，0 号槽就是第一个参数。访问一个 64 位局部变量时，指令只给出低位那个下标。

### 槽位可以复用

某个局部变量的作用域结束后，它占用的槽可以给后面声明的变量用。这能缩短表的长度。副作用是：若大对象的引用被后来的变量覆盖，这个对象可能在方法返回前就变得不可达。

```java
public class SlotReuse {
    public void scratch() {
        {
            byte[] block = new byte[512 * 1024];
            // block 的作用域到此结束
        }
        int marker = 7;
    }
}
```

若编译器让 `marker` 复用 `block` 的槽，`block` 在给 `marker` 赋值之后就不再是根。若没有复用，数组要等 `scratch` 返回才不可达。这不是收集器“提前回收局部变量”的特殊功能，只是槽里不再保存那个引用。

### 和类变量对照

按类型，变量分成基本类型和引用类型。按位置，分成类变量、实例变量和局部变量。

- 类变量在链接的准备阶段得到零值，在初始化阶段才执行源码里的赋值和静态块。
- 实例变量随对象在堆上分配，分配时同样先写零值。
- 局部变量没有准备阶段那种系统清零后给程序员用的过程。Java 语言要求局部变量在读取前必须被赋值，否则编译失败。虚拟机的字节码验证也会拒绝使用未初始化的槽。

参数表分配完之后，方法体内的局部变量按出现顺序和作用域占用后面的槽。和调优关系最紧的往往就是这张表：槽多则帧大，帧大则同样栈容量下的调用深度下降。它同时还是根枚举的一部分。

## 操作数栈

除局部变量表外，每一帧还有一个后进先出的操作数栈。字节码把值压进去，或从栈顶弹出后再把结果压回。复制、交换、加减都是这样完成的。它保存的是计算的中间量，也是执行引擎的工作区。方法刚进入时，这一栈是空的，但最大深度已经确定，写在 `Code` 属性的 `max_stack` 里。深度在编译期算好，运行中不会把某一帧的操作数栈再申请得更深。

32 位类型占一个栈单位，64 位类型占两个。操作数栈不能按下标随机访问，只能压栈和弹栈。被调用方法若有返回值，返回值会被压入调用者的操作数栈，同时程序计数器指向调用指令的下一条。

栈上元素的类型必须和指令匹配。编译器在编译时检查一次，类加载的字节码验证在数据流分析时再检查一次。人们说“Java 虚拟机的解释器是基于栈的”，指的就是操作数栈，不是指整个虚拟机栈这个容器。

### 跟踪一段加法

```java
public void mixAdd() {
    byte p = 12;
    int q = 7;
    int r = p + q;
}
```

`mixAdd` 是实例方法，0 号槽是 `this`。`javap -c` 看到的主路径类似这样：`bipush 12` 把 12 压入操作数栈，`istore_1` 弹到 1 号槽；`bipush 7` 再压入，`istore_2` 写入 2 号槽。相加前执行两次 `iload`，把 12 和 7 重新压回栈顶，`iadd` 弹出它们并压入和，`istore_3` 把和放进 3 号槽，最后 `return`。`byte` 在这里并没有专用的加法指令，提升为 `int` 后走 `iadd`。程序计数器每执行一条指令就指向下一条，方法结束时这帧弹出。

### `i++` 和 `++i`

两者都要改局部变量，差别在压回操作数栈的是旧值还是新值。对局部变量 `i` 而言，`i++` 是先 `iload` 再 `iinc`，栈上留下的是加一之前的值。`++i` 是先 `iinc` 再 `iload`，栈上留下的是加一之后的值。`iinc` 直接改槽位，不经过操作数栈。所以“`++` 只是语法糖、字节码完全一样”并不成立。

## 栈顶缓存

栈式指令紧凑，但每次运算都伴随多次内存读写。HotSpot 把操作数栈的栈顶元素缓存在物理寄存器里，减少访问内存中那块栈的次数。这项技术常被写成 Top-of-Stack Cache。它不改变字节码的含义，只改变解释器或编译管线内部的取数位置。寄存器指令少、单次访问快，缓存的就是这个好处，字节码本身仍然是零地址形式。

## 动态链接

每一帧都带有一个指向运行时常量池中“本方法”的引用。方法体里的字段访问和方法调用，在类文件中最初只是符号引用。动态链接要做的事，就是在需要时把这些符号变成直接引用。`invokedynamic` 也依赖运行时常量池里的引导方法信息。

符号引用集中放在常量池，而不是拷贝到每一个调用点，这样多个方法可以共用同一项描述。常量池提供名字、类型和常量，指令只保存指向它的索引。

## 方法调用：从符号到指令

把符号引用换成直接引用，和绑定时机有关。

### 静态链接与动态链接

若目标方法在编译期就能确定，并且运行期不会变成另一个方法，那么在装载或解析时把符号换成直接引用，称为静态链接。若编译期只能知道一个抽象的名字，要到运行期按实际类型选定方法，这次转换就是动态链接。这里的“动态链接”是绑定方式，和帧里那个常量池引用是同一件事的两面。

### 早期绑定与晚期绑定

绑定是字段、方法或类的符号被替换成直接引用的过程，对同一个调用点只做一次。编译期可知、运行期不变的目标，可以和方法所属类型提前绑死，这是早期绑定，对应静态链接。编译期无法确定、必须按运行期的实际类型选择，这是晚期绑定。

支持封装、继承和多态的语言，都会同时存在这两种绑定。Java 里普通的实例方法默认具备多态能力，相当于 C++ 里需要 `virtual` 才有的虚函数。不想被覆盖，就用 `final` 标在方法上，也可以把类标成 `final`。

### 虚方法与非虚方法

编译期就能定下唯一版本、运行期不再改变的方法，是非虚方法。静态方法、私有方法、实例构造器、父类方法调用，以及被 `final` 修饰的实例方法，都属于非虚方法。其余需要按实际类型派发的，是虚方法。形成多态要同时有继承和覆盖；没有覆盖，即使走虚调用指令，最终也只会落到父类那一份实现。

虚拟机提供的调用指令分成两组。

普通调用：

- `invokestatic` 调用静态方法，解析阶段就能定下唯一版本。
- `invokespecial` 调用 `<init>`、私有方法和父类方法，同样在解析阶段定版。
- `invokevirtual` 调用虚方法。
- `invokeinterface` 调用接口方法。

动态调用：

- `invokedynamic` 在运行期由引导方法决定本次要执行的目标，然后再调用。

前四条的派发规则写死在虚拟机里。`invokestatic` 和 `invokespecial` 调用的一定是非虚方法。`invokevirtual` 调用的多数是虚方法，但 `final` 方法虽然也可能以这条指令出现，绑定结果在运行期不变，仍然按非虚方法处理。

### `invokedynamic`

字节码指令集长期稳定，Java 7 才加入 `invokedynamic`，目的是支持动态类型语言，而不是为了改 Java 的语法。Java 7 的编译器不会因为普通方法调用就发出这条指令，当时要用 ASM 这类库自己生成。Java 8 的 Lambda 让 `javac` 第一次大规模产出 `invokedynamic`：Lambda 的方法体被放到合成方法里，调用点通过引导方法在运行期链接到该合成方法或方法句柄。

因此 Java 7 的这项改动改的是虚拟机规范，不是 `if` 和 `for` 的语言规则。最先受益的是跑在 JVM 上的动态语言编译器，后来才是 Java 自己的 Lambda。

### 静态类型语言与动态类型语言

区别在于类型检查发生在编译期还是运行期。静态类型语言检查变量声明的类型，动态类型语言检查值在那一刻的类型，变量本身可以先后指向不同类型的值。

Java 里 `String title = "north"` 在编译期就要求右侧是字符串。JavaScript 里同一个绑定可以先放字符串再放数字，要等运行到那一行才检查。Java 通过 `invokedynamic` 把“目标晚一点再定”的能力开放给了方法调用，但 Java 语言本身仍然是静态类型的。

### 覆盖时如何找到方法

`invokevirtual` 的派发可以概括成：

- 看操作数栈顶引用所指向对象的实际类型，记为 C。
- 在 C 中按简单名和描述符查找。找到后做访问检查，通过则返回直接引用；不通过则抛出 `IllegalAccessError`。
- 找不到就沿父类向上重复上一步。
- 直到 `Object` 仍没有相符方法，抛出 `AbstractMethodError`。

`IllegalAccessError` 表示运行期试图访问一个当前类无权使用的字段或方法。编译期通常已经拦住了私有成员。运行期还出现它，多半是两个类的版本不一致，例如调用方按旧的公开签名编译，被调用方后来把成员收紧了。

### 虚方法表

若每次虚调用都在元数据里线性查找，开销会落在热路径上。HotSpot 在类加载的链接阶段、准备完成之后，为类建立虚方法表，用下标代替按名字搜索。非虚方法不进入这张表。表项是方法的实际入口。子类覆盖了的方法，表里放子类的入口；没有覆盖的，入口仍指向父类甚至 `Object` 的实现。接口方法另有接口方法表，思路相同，结构分开。

## 方法返回地址

帧里可以保存调用方程序计数器的值，也就是调用指令的下一条。方法结束只有两类：

- 正常执行完，遇到返回指令。
- 抛出本方法没有处理的异常，非正常退出。

正常退出时，返回地址就是调用点的下一条指令。异常退出时，要查本方法的异常表才能知道控制权交给谁；对不上任何处理器，就把异常继续抛给调用者，帧里通常不额外保存一份“异常返回地址”。

返回指令按类型区分：`boolean`、`byte`、`char`、`short`、`int` 用 `ireturn`，`long` 用 `lreturn`，`float` 用 `freturn`，`double` 用 `dreturn`，引用用 `areturn`。`void` 方法、实例初始化方法和类初始化方法用 `return`。选用哪一条，由方法描述符的返回类型决定，不是由源码里变量的写法决定。

异常出口和正常出口的差别是：异常出口不会给调用者的操作数栈压入返回值。调用者若没有相应的异常处理器，自己的帧也会弹出。

方法退出的本质是当前帧出栈。虚拟机恢复调用者的局部变量表和操作数栈，必要时把返回值压入调用者的操作数栈，并设置程序计数器，调用者才能继续。

## 附加信息

规范允许帧携带与实现相关的额外数据，例如支持调试的信息。这些数据不影响操作数栈的运算规则，不同虚拟机可以有不同的布局。

## 常见问题

无界递归或过深的调用链会抛出 `StackOverflowError`。用 `-Xss` 可以改变发生溢出前的深度，但不能保证一个不收敛的递归永不溢出。把栈调大也不是单向收益：同样深度的调用更安全了，每条线程占用的本地内存却变多，进程能创建的线程数下降，更可能在 `new Thread` 时出现 `OutOfMemoryError`。

垃圾收集不回收虚拟机栈。帧随方法返回弹出。收集器只会把栈上仍然存在的引用当作根，去标记堆里的对象。

局部变量是否线程安全，要看对象会不会逃出当前线程，而不是看它是不是写在方法里面。

```java
public class BufEscape {
    public static void hidden() {
        StringBuilder buf = new StringBuilder();
        buf.append("k");
        buf.append("v");
    }

    public static StringBuilder leaked() {
        StringBuilder buf = new StringBuilder();
        buf.append("k");
        return buf;
    }

    public static void mutate(StringBuilder shared) {
        shared.append("k");
    }

    public static void race() {
        StringBuilder buf = new StringBuilder();
        new Thread(() -> buf.append("v"), "side").start();
        mutate(buf);
    }

    public static String snapshot() {
        StringBuilder buf = new StringBuilder();
        buf.append("k");
        buf.append("v");
        return buf.toString();
    }
}
```

`hidden` 里的缓冲区只在本线程创建和使用，没有交给别人，这个对象的操作是线程安全的。`leaked` 把同一个可变对象返回给调用方，调用方若再交给别的线程，就不再安全。`mutate` 操作的是外部传入的对象，方法自己无法保证只有一个线程持有它。`race` 让两条线程同时 `append`，`StringBuilder` 的内部计数会错乱。`snapshot` 返回的是不可变的 `String`，缓冲区本身没有逃逸，返回值可以安全地交给其他线程读。

一句话：对象在本线程内创建、只在本线程内使用，并且没有把引用交出去，对它的操作就是线程封闭的。引用一旦返回、传入或被别的线程捕获，就要按共享数据来保护。`StringBuilder` 这个类本身不是并发安全的，但线程封闭的实例不必再加锁。

各运行时区域是否会出错、是否参与垃圾回收，可以对照下面这张表。

| 区域 | 可能的错误 | 会不会被垃圾回收 |
| --- | --- | --- |
| 程序计数器 | 不会溢出 | 不回收 |
| Java 虚拟机栈 | 栈溢出或创建线程失败 | 不回收帧 |
| 本地方法栈 | 与 Java 栈同类的错误 | 不回收帧 |
| 方法区 / 元空间 | 元空间耗尽 | 会卸载不再使用的类 |
| 堆 | 堆耗尽 | 回收不可达对象 |

HotSpot 把两块栈合成一块，所以表里前两行的栈错误在实现上共用 `-Xss`。方法区在 JDK 8 之前是永久代，溢出信息的文字和元空间不同，但“会出错、类可以被卸载”这两点不变。

## 易错点

- 把对象说成“分配在栈上”时，要区分标量替换和真正的栈分配。局部变量里的引用仍然在帧里，普通 `new` 出来的对象仍在堆上。即时编译器在能证明对象不会逃逸时，可能把字段拆成标量放进寄存器或栈槽，这是优化，不是字节码规范规定每一帧都有对象头。
- `StackOverflowError` 是 `Error`，不是可恢复的普通业务异常。捕获它之后继续在同一条已经很深的调用链上分配，很容易再次失败。
- 操作数栈的深度不够会在验证阶段失败，而不是运行到一半再把帧调大。`VerifyError` 或类加载失败，常常是字节码工具改坏了 `max_stack`。
- `invokedynamic` 不是反射。反射走 `Method.invoke`，Lambda 的链接走方法句柄和引导方法，两条路径的开销和可见性都不一样。
