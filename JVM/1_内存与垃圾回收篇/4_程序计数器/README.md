# 程序计数器

## 介绍

虚拟机里的程序计数器，英文常写作 Program Counter，也被称作 PC 寄存器。Register 这个词来自处理器：CPU 取指、译码之前，得先把指令地址放进自己的寄存器。虚拟机借用了这个名字，但这块区域并不是主板上那枚物理寄存器，而是运行时数据区里用软件模拟出来的指令游标。把它理解成“当前线程下一条字节码的位置”，比理解成硬件寄存器更贴近实现。

它占用的空间很小，通常只是一个机器字宽的槽，读写路径也最短，所以是运行时数据区里速度最快的一块。虚拟机规范把它定为线程私有：线程出生时一起创建，线程结束时一起消失。任意时刻，一条线程只有一个当前方法。方法若是 Java 写的，计数器里记录的是下一条待执行字节码在该方法字节码数组中的偏移；方法若是 native 实现，这个槽的内容规范没有定义，实现可以把它看成无效值。

控制流里的分支、循环、条件跳转、异常表派发，以及线程被挂起之后再继续，都要靠这个偏移找回“执行到了哪里”。字节码解释器的主循环本质上就是：读出计数器指向的操作码，执行对应语义，再把计数器改成后续指令的位置。

规范为几乎每个运行时区域都描述了耗尽后的错误，唯独程序计数器没有 OutOfMemoryError。原因很直接：它不随方法嵌套而膨胀，也不存放对象，只是每条线程一个固定槽位。

## 作用

程序计数器保存的是即将被执行引擎取走的那条指令地址。调用 Java 方法时，当前偏移要先保护好，被调方法返回后才能从正确的下一条继续；解释器每完成一条指令，也会立刻更新它。可以把它看成解释器的取指指针。

## 代码演示

下面用一个只做加法的入口方法观察偏移。类名、立即数都换成了另一组，避免和常见演示撞车：

```java
public class InstructionCursorDemo {
    public static void main(String[] args) {
        int left = 7;
        int right = 13;
        int sum = left + right;
    }
}
```

用 `javap -c` 反汇编后，每条指令左侧的数字就是该方法字节码流中的偏移。下面是等价形状的清单，具体编码随编译器版本可能差一两个字节：

```text
0: bipush        7
2: istore_1
3: bipush        13
5: istore_2
6: iload_1
7: iload_2
8: iadd
9: istore_3
10: return
```

`bipush` 把单字节立即数压入操作数栈，`istore_1` 弹出并写入局部变量表第 1 槽。接着用同样的方式放下 13。两条 `iload` 把加数重新压栈，`iadd` 弹出两数、压回和，`istore_3` 把和写入第 3 槽，`return` 结束方法。程序计数器从 0 起步，执行完第一条后变为 2，再变为 3，逐步前移。这些数字就是它在这条方法里要记住的内容。

## 保存字节码地址解决什么问题

操作系统会按时间片把处理器从一个线程换到另一个线程。切走之前，这条线程的运算进度必须能原样恢复，否则重新获得处理器时会从错误的指令继续。Java 方法的进度就是字节码偏移，放在各自的程序计数器里。解释器也只认这个值：它决定下一拍译码的是加载、运算、跳转还是返回。

## 为何必须线程私有

在一个确定的瞬间，一个处理器核只执行某一条线程里的一条指令。时间片耗尽后，这条线程被挂起，另一条线程接上。如果所有线程共用同一个计数器，后执行的线程会把地址写坏，先前的线程就失去恢复点。所以线程对象创建时，会同时准备私有的程序计数器和私有的 Java 虚拟机栈。栈帧记录方法调用层次，计数器记录当前帧里执行到的字节码，两者互不覆盖。

## CPU 时间片

时间片是调度器分给线程的一段处理器时间。宏观上多个进程像在同时运行，微观上单核只能轮流执行。时间片由操作系统划分。Java 线程被换下时，靠私有的程序计数器记住字节码停在哪一条。
