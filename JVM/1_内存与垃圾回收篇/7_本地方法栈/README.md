# 本地方法栈

## 概念

Java 虚拟机栈记录 Java 方法的调用。本地方法栈负责 native 方法进入本地代码后的调用过程。它同样是线程私有的，线程结束时一起释放。

规范允许容量固定，也允许按需向操作系统继续申请。

## 分类与溢出

- 容量固定时，请求的栈深超过上限，虚拟机抛出 `StackOverflowError`。
- 允许扩张时，扩张失败，或新建线程时栈本身分配不出，抛出 `OutOfMemoryError`。

两条都和 Java 方法栈对称，触发者换成了 native 调用。

## 调用过程

规范不限定编写语言。HotSpot 上常见的是 C 或 C++。执行到 native 方法时，虚拟机在本地方法栈登记调用，执行引擎再装入动态库并把控制权交给库函数。

进入本地方法后，线程离开字节码解释器，权限与进程相当：

- 可以经本地接口访问堆、方法区等数据区。
- 可以直接使用处理器寄存器。
- 可以向本地堆申请内存。这块内存不受 `-Xmx` 约束，也不会随帧弹出被当成对象收回。

## 实现差异

规范只要求支持 native 的产品提供栈，不规定语言和数据结构。不支持 native 的虚拟机可以不实现它。

HotSpot 把本地方法栈与 Java 方法栈合成一块，`-Xss768k` 或 `-Xss2m` 同时限制两种调用，而且是每条线程一份。

## 易错点

本地方法栈是调用栈，不是直接内存。本地代码分配的块不在 Java 堆里，帧弹出也不会自动回收。`StackOverflowError` 也可能来自很深的 JNI 调用。创建线程失败时，堆也许仍有空闲，缺的是本地内存或线程配额。
