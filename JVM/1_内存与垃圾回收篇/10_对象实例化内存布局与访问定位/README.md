# 对象的创建、布局与访问

## 对象实例化

### 面试里会问什么

创建路径通常被连着问三件事：实例落在哪，对象头里有哪些字段，头本身由哪几截拼成。按步骤说完，三问会一起被回答掉。

### 创建对象的途径

- `new` 最常见。单例工厂、各类 `Factory` 的静态方法，最后多半也回到它。
- `Class.newInstance()` 只能调用公有无参构造，JDK 9 起被标为过时。
- `Constructor.newInstance(...)` 走反射，无参或带参都可以，异常包装也不同。
- `clone()` 不走构造器，类必须实现 `Cloneable`。
- 反序列化按序列化协议还原对象，同样不调用普通构造器。
- Objenesis 这类库能在不调用构造器的前提下造出实例，多见于模拟框架。

### 创建对象的步骤

#### 类是否已经加载、链接并初始化

解释器或编译后的代码遇到 `new`，先用常量池索引到元空间中的运行时常量池，确认类已经完成加载、解析和初始化。

若类还不存在，就按双亲委派，用“加载器 + 全限定名”去找字节码。找不到则抛出 `ClassNotFoundException`。找到了就完成加载，并在堆上生成对应的 `Class` 对象。类初始化只发生一次。

#### 为对象划分内存

先按字段布局算出实例需要多少字节，再在堆里划出同样大小的一块。引用字段只留引用槽：压缩普通对象指针打开时通常 4 字节，关闭时 8 字节，不会把被指对象嵌进来。

堆是否规整，决定分配策略。规整时用指针碰撞：已用和空闲各占一边，中间一个指针，新对象只是把指针挪过对象大小那么多。Serial、ParNew 这类会压缩的收集器能保持这种形态。不规整时用空闲列表：虚拟机记录可用区间，找一块够大的切给对象，再更新表项。CMS 的老年代就是这样。选用哪一种，根上取决于收集器会不会把存活对象挪到一起。

#### 处理并发

堆被所有线程共享，分配指针不能被并发写坏。HotSpot 用两种办法：CAS 配失败重试；或者给每条线程一块 TLAB，在 Eden 里私有地推进指针。开关是 `-XX:+UseTLAB`，默认开启。TLAB 放不下时才退回慢路径。

### 把分到的内存初始化掉

划出来的内存先做零值填充：数值为 0，布尔为 false，引用为 null。因此字段即使没写初值，读到的也是类型默认值。程序员能看到的赋值在后面，顺序是字段声明上的显式初值、实例初始化块、构造器体。这三步都进了 `<init>`，并且排在父类构造器之后。

### 设置对象头

零值写完后填写对象头：所属类的元数据指针、哈希相关信息、分代年龄、锁状态。哪些比特放在哪一位，由实现决定。

### 执行 init 完成初始化

到这里，从 Java 程序看对象还不能用。`new` 后面紧跟 `invokespecial`，调用 `<init>`。其中会调用父类构造器，执行字段显式初值和实例块，再执行构造器体。完成后，实例起始地址写进调用者的引用变量。

### 实例化过程串起来

1. 确认类元信息可用，不够就先加载并初始化类。
2. 按对象大小在堆上分配。
3. 用 TLAB 或 CAS 处理并发。
4. 零值初始化。
5. 填写对象头。
6. 执行 `<init>`。

## 对象内存布局

HotSpot 把普通对象分成三截：对象头、实例数据、对齐填充。数组会在对象头里多一个长度。

### 对象头

对象头至少包含运行时元数据（Mark Word）和类型指针。数组还要记录长度，否则不知道元素区到哪里结束。

#### 运行时元数据

Mark Word 的比特在不同锁状态下复用。无锁或偏向相关时，常见内容包括：

- 哈希码，可以拖到第一次调用 `hashCode` 才写入。
- 分代年龄。只有几位，所以上限是 15。
- 锁标志，区分无锁、偏向、轻量级和重量级。
- 持有轻量级或重量级锁时，改记指向锁记录或监视器的指针。
- 偏向线程的标识，以及偏向时间戳。

同一组比特不会同时放下所有含义。进入偏向锁定后，身份哈希的位置会让给线程标识。

#### 类型指针

类型指针指向元空间里的类元数据，HotSpot 中是 `InstanceKlass`。字段扫描、类型检查和虚方法分派都靠它。压缩类指针打开时，它可以是 4 字节。

### 实例数据（Instance Data）

实例数据是字段的有效载荷。父类字段排在子类字段之前。HotSpot 还会按宽度把字段分组，减少中间空洞。静态字段不在这里，它们跟类走，不跟某一个实例走。

#### 说明

对象末尾常常还有对齐填充。它不表达业务字段，只是把整个对象补到 8 字节的整数倍。前面已经对齐时，这段可以不存在。填充让下一个对象的起始地址继续满足对齐。

### 小结

先读 Mark Word 判断锁和年龄，再读类型指针找到类，然后按类的布局解释后面的字段。总长度不是 8 的倍数时，尾部补齐。数组则在类型指针之后先读长度。

## 对象的访问定位

### 访问路径

栈帧的局部变量表或操作数栈里保存的是引用，不是对象本体。虚拟机必须规定：顺着这个引用怎样找到堆里的实例，又怎样找到方法区里的类型数据。主流有两种设计。

### 两种访问方式

#### 句柄访问

reference 不直接指向实例，而是指向堆中的句柄池。每个句柄至少放两个地址：实例数据，以及类型数据。对象被移动时，只改句柄里的实例指针。

#### 优点

引用里的句柄地址可以保持稳定。复制、整理都会搬运对象，此时只更新句柄，栈上和堆上的 reference 都不用改。代价是每次访问多一次间接寻址。

#### 直接指针（HotSpot 采用）

HotSpot 让栈帧槽位里的 reference 等于实例起始地址，中间不再绕一层句柄。类型数据靠对象头里的类型指针进方法区。访问字段少一次跳转。对象被移动时，所有指向它的引用都要由收集器修正。两种方案都能完成定位，HotSpot 选择了直接指针。
