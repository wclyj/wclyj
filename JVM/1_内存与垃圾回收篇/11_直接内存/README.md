# 直接内存 Direct Memory

直接内存不属于运行时数据区，也不在《Java 虚拟机规范》列出的区域里。它位于 Java 堆之外，向操作系统另行申请。

NIO 把它引进来：堆内的 `DirectByteBuffer` 只是壳，真正的缓冲在堆外。少一次堆与内核之间的拷贝，批量读写往往更快，高吞吐的通道会选用它。

下面只申请 64MB：

```java
int capacity = 64 * 1024 * 1024;
ByteBuffer buffer = ByteBuffer.allocateDirect(capacity);
```

## 堆内缓冲与堆外缓冲

阻塞流的路径是：Java 数组先放在堆里，系统调用前再拷进内核缓冲，返回时拷回。一次读写至少两份复制，还要在用户态和内核态之间切换。

NIO 把缓冲变成显式对象。直接缓冲的地址可以被本地 I/O 直接使用，少掉那次额外复制。壳对象仍在堆上，变得不可达之后，由清理器把堆外内存还回去。

## 容量与失败

堆外一样会耗尽，错误是 `OutOfMemoryError`，信息里带有 Direct buffer memory。它不受 `-Xmx` 单独封顶，但 Java 堆与直接内存之和不能超过操作系统还能给出的上限。

申请和归还走本地分配器，比在 Eden 里移动指针贵；归还也不跟着一次普通的年轻代收集立刻发生。因此直接缓冲适合长期复用，不适合在循环里反复创建。

上限由 `-XX:MaxDirectMemorySize` 控制。省略时，默认跟 `-Xmx` 取齐。
